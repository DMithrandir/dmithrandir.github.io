> **一句话**：政策级联的失败，通常不是「传达不到位」，是**三次转手没有 owner**。

## 00 · 开篇：一条政策，三个基地，三种判法

- 场景（示意）：同一条政策下发后，三个基地对同一类 case 判出三种结论；培训记录都完成了。
- 问题不是「没培训」，是**语义、组织、系统三层没有对齐**。
- 本文回答三件事：一条政策要过哪几关；知识系统在其中做什么；怎么知道它没散。
- 判断：**政策级联不是一条线，是三张网。**

## 01 · 三种一致性：语义、执行、版本

- **语义一致性**：同一条政策，在不同市场、语种、角色上被理解成同一件事。
- **执行一致性**：不同审核员对同一类 case 判出同一结论（一致性 κ 可测）。
- **版本一致性**：文档、提示词、检索库、模型、判例引用的是同一版。

| 一致性 | 失败长相 | 通常归谁 |
|---|---|---|
| 语义 | 一线靠经验补；同词不同解 | 政策 / 策略 |
| 执行 | 培训了，判得还是不一样 | 运营 / 培训 / QA |
| 版本 | 各说各话；引用过期条款 | 产品 / 工程 / 知识运营 |

- 判断：**三种一致性缺一个，另外两个就会用「经验」和「例外」来补，系统开始漂。**

## 02 · 三层级联

| 级联 | 从 → 到 | 失败长相 | owner |
|---|---|---|---|
| **语义级联** | 政策条款 → 可执行判据 | 一线靠经验补 | 政策 / 策略 |
| **组织级联** | 总部 → 市场 / 基地 / 审核员 | 培训了但判不一致 | 运营 / 培训 |
| **系统级联** | 文档 → 提示词 / 检索 / 模型 / 判例 | 版本漂移、各说各话 | 产品 / 工程 / 知识运营 |

- 判断：**三层必须同时过；只做组织级联，等于把语义和系统的债留给一线。**

## 03 · 语义级联：条款 → 判据

- 判据五要素：**主体 / 行为 / 对象 / 情境 / 证据**（+ 处置）。
- **可判定 vs 不可判定**：形容词不是判据；「低俗 / 误导 / 对立」要落到行为与情境。
- **例外与灰度**：「判不了」也是判据的一部分——Edge / 升级出口 / 规则空白。
- 一行示例：

| 条款 | 判据（五要素） | 执行形态 |
|---|---|---|
| 不得发布低俗内容 | 主体：普通用户；行为：刻意展示；对象：身体部位；情境：非教育/非医疗；证据：画面 + 上下文 | 标签 + 机审分 + 人审 |

- 语义级联的完整拆解见系列 01「一条规则要经过几次翻译」（**待上线；上线后再补链接**）；那篇讲「五次转手」，本文不重复。

## 04 · 组织级联：总部 → 市场 / 基地 / 审核员

- 角色：政策 owner / 判据 owner / 培训 / QA / 申诉 / 区域。
- 多市场、多语种：**不是翻译，是本地判例 + 文化语境 + 本地裁决权**。
- 培训、考试、校准、抽检：培训完成 ≠ 判得一致；用考试、κ、抽检验证。
- 判断：**组织级联的终点不是「培训完成率」，是「执行一致率」。**

## 05 · 系统级联：文档 → 提示词 / 检索 / 模型 / 判例

- 同一条规则住在几个地方：文档、提示词、检索库、判例、代码分支、培训课件。
- 版本漂移的四种长相：
  1. 提示词为挡新变体临时加一句，事后没回写条款；
  2. 条款改了，检索索引没重建；
  3. 新判例入库，旧判例没标失效；
  4. 培训还在按上一版讲。
- 判断：**系统级联的核心不是「上一个系统」，是「声明哪一份算数」。**
- 链接：[SSOT 与迭代流程]({{ '/governance/11-ssot/' | relative_url }})。

## 06 · 知识系统：不是文档库，是三层 + 契约

- 三层：
  - **Policy**：条款 + 可执行判据（结论必须引它）。
  - **OG（Operation Guideline）**：看到什么 → 按什么顺序判 → 判不了怎么办。
  - **Case**：正例 / 反例 / 边界；只作参照，不立法。
- 元数据：`policy_id / version / as_of / market / authority / ACL`。
- 检索契约：问答、判定、申诉、培训、RCA、审计，各自取什么证据包。
- 三条硬约束：**判例不立法；无条款只 Edge；as-of 不可省。**
- 判断：**知识系统解决「知道 / 做到 / 拿不准」三件事，不是「存文档」。**

## 07 · 上线闸门：一条政策上线前要过五关

| 闸门 | 问什么 | 不过的后果 |
|---|---|---|
| **可判定性** | 条款能不能拆成判据 | 一线靠经验 |
| **可执行性** | 一线能不能照着判（κ） | 判不一致 |
| **检索** | 知识系统找不找得到、引用对不对 | 找不到 = 不用 |
| **灰度** | 小流量、护栏、回滚 | 误伤 / 漏放同时涨 |
| **版本** | as-of / 变更日志 / 旧版失效 | 各说各话 |

- 判断：**上线闸门不是流程审批，是「证据齐不齐」。**

## 08 · 回流：申诉 / 质检 / 归因 → 四通道

- 申诉、质检、抽检 → 结论码：审核员错 / QA 错 / 都错 / 规则空白。
- 四条改进通道：**规则补丁 / 产品切片 / 队列补全 / 质量培训**。
- 每个码映射一个动作、一个 owner、一个验证方式。
- 判断：**没有回写的政策级联，只是一次性下发。**

## 09 · 指标：怎么知道它没散

| 层 | 主指标 | 反指标 |
|---|---|---|
| 语义 | 判据覆盖率 / 规则空白占比 | 覆盖率 ↑ 但误伤 ↑ |
| 执行 | 一致性 κ / 首次下发准确率 | 周期 ↓ 但一致性 ↓ |
| 系统 | 检索命中 / 引用失效率 / 版本漂移数 | 使用率 ↑ 但命中 ↓ |
| 组织 | 培训完成 / 考试通过 / 校准闭环 | 完成率 ↑ 但抽检差 |
| 成本 | 政策周期 / AHT / 单案成本 | 成本 ↓ 但漏放 ↑ |

- 判断：**主指标 1 个、护栏 2–3 个、诊断 5–8 个；没有反指标的看板会教一线「先拒后放」。**

## 10 · 最小落地顺序

1. 统一元数据（`policy_id / version / as_of / market / authority / ACL`）。
2. 选一条政策做判据化试点（五要素 + OG + 正反例）。
3. 建可执行性测试（20–50 条边界 case，跑 κ）。
4. 建检索契约（条款 / OG / 判例三层）。
5. 接回流（四类码 / 四通道）。
6. 上配对看板（主指标 + 反指标）。

- 判断：**不要先买系统；先定口径，再上工具。**

## 11 · 收尾

- 政策级联的终点不是「发下去」，是**「判得一致、改得回来」**。
- 知识系统不是文档库，是这条链路的**唯一事实源**。
- 一句话：**级联是把政策送到一线，知识系统是让一线拿到的还是同一份。**
