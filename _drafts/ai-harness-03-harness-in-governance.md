## 这篇要回答

1. 内容治理里哪些环节适合放进 harness，哪些不适合？
2. 「人机三票」在 harness 里怎么表达，而不是写死在提示词里？
3. 怎么保证模型的判断可追溯、可复核？

## 结构

### 1. 先分清三类环节

| 环节 | 适合 harness？ | 原因 |
|---|---|---|
| 规则匹配、字段抽取 | 适合 | 结果可验证 |
| 语境判断、常识推理 | 部分适合 | 需要结构化输出 + 升级出口 |
| 政策制定、争议裁决 | 不适合 | 责任在人 |

### 2. CoT 四要素落成字段

- 信号类型 / 房间整体 / 常识推理 / 一句话结论
- 四要素不是让模型「写作文」，而是让失败可归因
- 待补：字段在 harness 里是 JSON schema 还是自然语言段落

### 3. 三票与升级

- 两个模型 + 一位人工，同时判定、互不可见
- harness 负责：并发、盲评、多数决、分歧时升级
- 关键设计：人票不是「兜底」，是「决定性一票」

### 4. 可回放

- 每个案例存：输入、四要素输出、三票结果、最终结论
- 回放的价值：改一个字段，能重跑同一批案例
