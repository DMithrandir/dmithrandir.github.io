# 一、博客主线（建议叙事结构）

1. **开篇冲突**：大模型来了，机审小模型是不是要被淘汰？——答案是反的：小模型没被淘汰，**位置变了**。
2. **起点**：快手 KDD 2025 的 common law 框架（判例法 vs 大陆法系的比喻，以及它真正做了什么）。
3. **演进**：机审从"规则+关键词"→"判别式小模型"→"大模型辅助人审"→"**大模型造数据、小模型全量、大模型兜底**"。
4. **机制**：为什么小模型必须在前置？——用**吞吐数字**回答，而不是用"成本更低"这种空话。
5. **分歧点**：政策到底放在哪？Prompt / 检索库 / 权重 / 判例库 —— 四种位置的真实取舍。
6. **商品治理**：另一条线，瓶颈不在识别率，而在**规则变更效率与商品全生命周期回扫**。
7. **收尾**：变的不是模型，是**审核组织的岗位定义**（规则表达式 → Prompt Engineer → RAG 运营 → 模型教练）。

## 2.2 "common law" 到底比喻什么

原文 §1 的论证：短视频平台传统审核范式等价于**大陆法系（civil law）**——平台先立"成文"规则体系，审核员扮演"法官"，先学规则再逐条遍历判定；代价是审核员心理负担、人力成本、且易受个体偏见影响。

KuaiMod 反过来仿效**判例法（common law）**：不依赖静态法条，而以既有"判例"（case/precedent）为判定依据——判例本身代表共识、并随社会演进持续更新，灵活性更高。

**三条动机（原文 bullet，可直接翻译引用）**：

1. **Complex Content Understanding**—— 小模型不懂视频语义，LLM 又处理不了复杂多模态、更没法从用户视角评估
2. **Rapidly Evolving Trends**—— 趋势快变，静态规则/模型不完备，更新周期长
3. **Deployment Requirements**—— 百万级日活与日上传，对准确率和成本都苛刻，既有研究**无工业部署验证**

⚠️ 原文**没有**"规则爆炸（rule explosion）""跨域不一致"的措辞——这两个说法属**未证实**。

## 2.3 系统三段结构

| 阶段 | 做法 | 关键细节 |
|---|---|---|
| **数据构造**| **Tag2CoT → CoT2Tag**双流程 | Tag2CoT：给定 metadata + 人工违规标签，让 **YuanQi-20B**反向生成"为何属于该标签"的因果分析。CoT2Tag：整理为**五状态转移**工作流 |
| **离线适配**| YuanQi-7B 后训练 | 大规模 SFT → **mistake-oriented DPO**（同一样本多次采样，取对/错回答配对） |
| **在线部署与精修**| **RLUF**（RL from User Feedback） | Environment=平台视频与用户；Agent=KuaiMod；**Reward 由全站举报率定义**；只取"模型判定与用户感知不一致"的争议样本；**数百条数据即可天级更新**；线上仍用 DPO，负例全部由线上模型自采样 |

**五状态转移工作流**（可直接画图）：
内容提取 → 视频内容分析（描述/标题/OCR/ASR **依次**排查）→ 中期检查 → **用户反馈分析（引入评论判断对观众影响）**→ 总结判断（输出标签 + 关键理由）

**基座 YuanQi**：EVA2-CLIP-E-Plus 视觉编码器 + Qwen-14B-Chat 1.0 作 LLM backbone，Flamingo 式架构，每层 transformer 前插 Gated Cross-Attention，含 MoE；规模 3B–20B，**20B 造数据、7B 落地**。前身技术报告：[EVLM, arXiv:2407.14177](https://arxiv.org/abs/2407.14177)。

**分类体系**：1 正例 + 15 违规标签，归 4 大类（法律与社会安全 / 内容质量与伦理 / 不良商业行为 / 侵害知识产权）。**线上已扩到 100+ 标签，并作为快手视频审核的参考体系**。

**标签扩张机制（值得单独讲）**：审核员遇到归不进现有体系的案例 → 让 YuanQi-20B 生成补充二级标签 → 聚合后人工复核入体系。

## 2.5 ⚠️ 引用这篇论文时必须带上的限定

1. **−20% 的适用范围不是全量内容**。线上 A/B 只对**举报次数 ≥5 次**的视频送 KuaiMod 做细粒度判定（原文 §6.2.1 明确用于 "narrow the moderation scope"）。省略这个前提会把数字作用域放大成"全站治理效果"。
2. **"20%" 与 "26%/24%" 是两个口径**。机器之心那篇里"主站下降超 26%、极速版超 24%"描述的是快手**多模态大模型体系整体**，不是 KuaiMod 单独结果。
3. **论文里没有"多模态聚类 / rule mining / codebook / 规则检索召回"**。这套能力在另一场演讲里（见 §三）。
4. **基座是 YuanQi，不是 Keye-VL**。作者名单高度重叠、Keye 报告引用了 KuaiMod，但官方从未声明 Keye 用于审核。
5. **没有独立 Limitations 章节**；A/B 增益仅 0.01–0.06% 量级且**未披露显著性**；在线负例全部由线上模型自采样，**存在自举偏差可能**【推断】。

## 2.6 QPS 6.81 到底意味着什么（本文最值得写的推算）

- 6.81 QPS × 86,400 s ≈ **588,000 条/日**，而论文写的日均审核量是 **600,000 条/日**→ **几乎完全吻合，说明这套集群是卡着 100% 利用率设计的、没有冗余**
- 摊到单卡：6.81 ÷ 48 ≈ **0.142 QPS/卡**，即**单张 4090 跑一条视频判定约需 7 秒**
- 对照淘天生鲜（见 §六）：**双卡 L20 跑单图 VQA 约 10 QPS**（单卡 5 QPS，约 0.2 秒/条）
- → **视频级多帧 VLM 判定与单图 VQA 判定之间有约 35 倍的吞吐差**

**这一步推算是全篇最有力的论证**：大模型视频审核不是"贵一点"，而是**比图片审核贵一到两个数量级**，所以"前置小模型"不是优化项，而是**前提**。

# 三、快手的另外两条技术线（数字更密）

## 3.1 主站安全大模型（刘梦怡团队）——方法论最完整，但零公开指标

来源：[AICon 深圳 2025 演讲实录（InfoQ）](https://www.infoq.cn/article/6r251b2u2bdaqmgbisfa)｜[安全内参全文转载](https://www.secrss.com/articles/86315)

**挑战描述极精确（可整段引用）**：
- 底线风险**仅占千分之几流量**（长尾且异常）
- 对抗变异强：谐音、形近字、**AIGC 低成本生产的风险样本**
- 尺度主观：泳装/护士装/制服在特定场景下的擦边定义
- 依赖专业知识（违禁品、隐晦表达）且要防灾难遗忘

**架构与训练**：
- **早期融合（early fusion）**：CLIP-ViT + 线性 MLP connector + LLM（理由写明"MLP 更简单、信息折损小"，**不用**交叉注意力深度融合）
- 三阶段：图文对齐预训练（**冻结 LLM 全部参数**，只训 encoder+connector）→ 多任务 SFT（微调 connector + LLM 部分层）→ RL（**人工偏序标注，reward 不仅看答案还要给中间推理证据链打分**）
- **数据配比消融：阶段一 开源:业务 = 4:1 ~ 5:1 最优；阶段二 4:1**。原文点出"业务数据占比过高会**抑制通用能力**（表征/语义理解）"

**蒸馏的双框架（"大模型→小模型"最直接的方法论）**：

| 框架 | 蒸馏方式 | 适用 |
|---|---|---|
| **生成式框架**| 黑盒 / response-level | 能**保留大模型的推理能力**|
| **判别式框架**| 白盒 / logits、feature-level（支持中间层连续数值输出） | **离散分类打标任务性价比更好**|

并受 DeepSeek-R1 启发做"**数据蒸馏 + GRPO**"。

**开集 Tagging（小模型侧的杀手能力）**：one-hot/multi-hot 稀疏标签 → 自然语言稠密向量表示，新风险类**只需一条文本描述即可零样本扩展，无需重训——"语义热插拔"**；配 Triplet alignment encoder（图像-描述 InfoNCE、图像-标签双向交叉熵）。

**标签体系三步（这才是"规则挖掘 + 规则库映射"的出处）**：
1. 多模态大模型自动描述内容得基础图文标签
2. **基于多模态内容表征聚合出一批同类型内容**→ 归纳风险元素 → 生成**结构化标签树**（二元组定层级 + 语义一致性/概念共现性滤噪）
3. 人工辅助校验标签体系与审核规则映射，**用大模型做标签-规则条款自动匹配与冲突校验**

产出变化：从"单一粗标签（软色情低俗）"→"**结构化描述 + 层级标签 + 规则条款推荐**"。

**安全知识库 + Advanced RAG**：知识分层（以平台规则为中心挂知识点与案例）→ 结构化管理 → 多模态多索引（文本倒排 + 表征向量 + **人物-事件关系图谱**）→ 前置 query 改写扩写（**同义/音近/形近词库**专门应对对抗变体）→ 后置精排/混排/图检索。

⚠️ 这场演讲**全文没有任何 QPS / 延迟 / GPU / 人审下降比例数字**。任何声称来自该演讲的"人审下降 X%"都是二次演绎。

## 3.2 商业化风控「明镜大模型 KwaiBLM」——数字最密的一条线

来源：[快手技术官方号（SegmentFault）](https://segmentfault.com/a/1190000046808383)【官方】

- **AWQ 量化：13B 模型权重 26.2G → 7.25G**（量化前对权重做常量缩放 + **保护 1% 显著权重**；RTN 忽略显著权重故效果差）；配 vLLM/PagedAttention
- 微调两阶段：Stage1 冻结图像+文本编码器只更新投影矩阵 → Stage2 继续冻结图像编码器、重新激活文本编码器与投影矩阵；对比全参数微调 vs LoRA
- **AhaEdit**：把"拦截终点"变成"内容修复起点"，闭环**审核—定位—修复—再审核**；文字定位到词/片段、图像给包围框、**视频精确到起止时间戳**；架构上抛弃"先识别类型再定位区域"的两阶段流水线（误差累积），改为 DiT 主干 + LoRA 的**识别与定位一体化端到端模型**；规模是**每天审核数亿创意**、自动修复上百万条素材

**磁力引擎风控负责人王东旭的口径（[AICon 北京](https://news.qq.com/rain/a/20260506A059W100)）**：

| 指标 | 数值 |
|---|---|
| 7B 模型对标 | 开源 **32B 甚至 72B**级别，**年度节约千万量级**|
| 蒸馏后学生模型 | **对齐大模型 70%–80%**的核心能力 |
| 前置小模型路由 | **拦截过滤逾 80%**常规简单案例 |
| Prompt 体系覆盖 | 约**八成**常规场景 |
| 组织指标 | 代码 AI 自动入库率 **>35%**；智能标注自动化率目标 **≥70%**；**日均 Token 消耗 1 亿**|
| 明确表述 | **"部分一线审核员实际上已经被大模型替换掉了"**|

**运营岗三级跃迁（本文建议作为收尾金句）**：规则表达式 → Prompt Engineer → **RAG 运营**→ **模型教练**（2025 Q3 把 SFT 做成线上化平台，**由运营直接运维模型 pipeline**）

其他技术点：视觉表征层基于 **SigLIP**自研对比学习；**mid-training**用海量图文风控数据在 LLaVA/QwenVL 式基座做领域增量续训；后训练 **DPO**（人工复核结果构成"判定偏好对"）+ **GRPO**（成果被 AAAI 2026 录用）。

## 3.3 BLM-Guard（AAAI 2026）——商业化广告可解释审核

- [arXiv:2602.18193](https://arxiv.org/abs/2602.18193)（2026-02-20）｜[AAAI OJS](https://ojs.aaai.org/index.php/AAAI/article/view/40914)
- **完整标题**：*BLM-Guard: Explainable Multimodal Ad Moderation with Chain-of-Thought and Policy-Aligned Rewards*
- 方法：规则驱动 **ICoT**数据合成 + **RL 复合奖励**（平衡因果一致性与政策遵从）+ **多任务架构**（同时建模模态内操纵如夸张画面，与跨模态不匹配如**字幕-语音漂移**）
- 实测：**w-Acc 0.962 / s-Acc 0.914 / 风险类 F1 0.969 / 一致性 0.845**，全面超 QwenGuard-7B（w-Acc 0.582）、LlavaGuard-7B（0.255）、Qwen2.5-VL-7B（0.712）、InternVL3-8B（0.389）
- 发布 BLM-Guard Benchmark：三级风险体系（Severity / Scenario / Violation Type），5–45s 商业广告

## 5.1 机审的四段演进

## 5.3 三级级联的工程形态与成本最优

- **FrugalGPT**（[arXiv:2305.05176](https://arxiv.org/abs/2305.05176)）：匹配 GPT-4 性能同时**降本最高 98%**
- **RouteLLM**（[arXiv:2406.18665](https://arxiv.org/abs/2406.18665)）：人类偏好数据训路由器，**降本 2 倍以上**
- **RADAR（ACL 2026 Industry）**（[论文](https://aclanthology.org/2026.acl-industry.139/)）：审核专用指标 **APR@R90/R95**（守住 90%/95% 召回下最大化流量旁路率）与 **R@P60**；实测**旁路 >80% 流量**；Qwen3-VL-8B 当教师逐类 KL 蒸馏 → **蒸馏后 4B 学生反超教师专家**；Qwen3-VL-2B→4B 使 PR-AUC 68.16→70.38
- **⚠️ RADAR 暴露的工业级隐性坑**：把"跨标注管线割裂导致的缺失标签"当负样本，会让 0.5B 骨干的 **R@P60 掉 18.42 分（43.77→62.19）**
- **CAUC（校准感知不确定性级联）**（[arXiv:2609.11446](https://arxiv.org/abs/2609.11446)）：跨模型置信度不可比，**必须先校准再设阈值**；六语言基准上相对"只用强模型"**平均相对精度 +1.9%**，同时**省掉约 47% 的强模型调用**；图像分类 GFLOPs **最多降 57%**
- **COGNIT-Guard**（[arXiv:2609.33671](https://arxiv.org/abs/2609.33671)）：**322M 双向直接判定模型**（Laya-322M）在 Ascend 910C 上**纯 NPU 21.77ms / 45.90 QPS**；线上串行 CPU-NPU 级联（θ*=0.70）**41.63ms**（P50 39.47ms，准确率 99.23%，**FPR 0.00%**）；DUCS-Bench 干净未见集（N=607）准确率 **98.85%**、良性 FPR **0.42%**、**ECE 1.12%**、Brier 0.0104
  - **摘要里最值钱的一句——小模型的"对齐税"**：Laya-322M 域外性能 **60.33% → 56.81%**（域内微调的 CLM-8B 只有 55.10%）；用 **experience replay 回放**才把 OOD 恢复到 **64.10%–65.05%**，同时域内保持 99.67%–99.84%
  - → **治理场景的对抗变异恰恰全是域外的（谐音/形近字/AIGC 新样本），所以小模型上线必须配 experience replay 或持续回流**

## 5.4 视频审核的生产级评测（稀缺数据点）

[arXiv:2512.03553](https://arxiv.org/abs/2512.03553) —— 少见的"已上线 + 大 A/B + 按精度锚定召回率"的直播审核论文
- **双管线**：分类管线打已知违规，**67% recall @ 80% precision**；相似度检索管线打新颖/隐性违规，**76% recall @ 80% precision**
- 文本、音频、画面**同时进两条管线**（不是先降维成文本）
- **MLLM 只当蒸馏教师，不做线上判定器**（与快手"20B 造数据、7B 落地"同范式）
- 大 A/B：**不良直播的用户观看量下降 6~8%**
- **意义**：在 80% 精度约束下，生产级直播审核召回大致在 **70% 上下**，且"新颖/隐性违规"靠**检索管线**召回反而更高——这直接支持"判例库检索"优于"扩标签再训分类头"

## 5.5 部署与性能工程

- **vLLM 官方实测**（[GPUStack 基准文档](https://github.com/gpustack/gpustack/blob/main/docs/performance-lab/references/the-impact-of-quantization-on-vllm-inference-performance.md)）：静态 **FP8 +26.7% TPS / TTFT −20.4% / TPOT −32.4%**；动态 FP8 +14.8% TPS；**显存不受限时纯 weight-only INT4 因反量化开销导致 TPS/TTFT/TPOT 全面退化**；weight-only 中 AWQ/GPTQ 最优；INT4-AWQ 在 Qwen3-8B 上 CEVAL 79.27→76.15
- **引擎分工**：生成式小 LLM（0.5B–4B）→ vLLM/SGLang/TensorRT-LLM + FP8；**判别式/双向模型 → ONNX Runtime/OpenVINO INT8 + CPU**（小模型审核最省钱的路子）
- **Multi-LoRA**：S-LoRA 单卡服务**数千 adapter**、吞吐**最高 4×**（[arXiv:2311.03285](https://arxiv.org/abs/2311.03285)）
- **视频降维路径**：镜头切分/关键帧抽取 → 音频轨 ASR → 字幕与画面 OCR → 压成"**文本 + 少量关键帧**"，让**文本小模型承担主要判定负载**。Keye-VL 模型卡里"单图视觉 token 可在 4–20480 之间调"就是最直接的成本杠杆
- **跨模态一致性作高风险信号**【推断】："字幕 vs ASR vs 画面 OCR"相互矛盾（字幕规避、语音违规但字幕干净）→ 直接触发人审

## 5.6 线上指标：不要看准确率

- **VVR（Violative View Rate）**：YouTube 自 2020Q4 起按季披露，公开历史值长期在 **0.1%~0.2% 量级**【官方报告】
- 配套指标集：漏放率、误伤率、申诉率与申诉成功率、转人工率、SLA（P50/P99）、自动处置占比
- **闭环核心不是"准确率"，而是"给定误伤约束下最大化自动处置量"**
- **漂移触发三层**【推断+论文】：① 统计层——输入/判定分布 PSI、KL 超阈；② 质量层——gold set R@P 衰减、申诉成功率突升；③ 攻击层——红队新攻击成功率上升（可参考 [DriftGuard, arXiv:2606.28725](https://arxiv.org/abs/2606.28725)）

# 六、商品治理：另一条线

## 6.1 任务拆解（五层，按风险载体）

1. **文本层**：违禁词、极限词、虚假宣传、医疗功效违规、资质文本
2. **图像/视频层**：假冒 logo、涉黄涉暴、图文不一致（**Logo 识别被论文点名为商品审核的核心挑战**，[Logo-VGR](https://arxiv.org/abs/2509.25811)）
3. **结构化层**：类目错放、SPU/CSPU 同款识别、属性缺失与不一致——**最隐蔽，却直接影响搜索召回与比价**
4. **交易信誉层**：刷单、销量作弊、评论与问答造假、价格欺诈
5. **直播层**：口播话术、画面违规、功效夸大

**关键变量是"规避型违规"**：分词、谐音、委婉语、裁图专门用于绕审（系统化评测见 [EVADE-Bench, arXiv:2505.17654](https://arxiv.org/abs/2505.17654)：26 个 LLM/VLM 评测，SOTA 仍频繁误判；**更清晰的规则分档显著提升预测一致性、降低误判**）。

## 6.2 架构与分工

**级联形态**：规则引擎 + 关键词 + OCR/以图搜图 → 轻量判别模型首筛 → 大模型兜底 → 人工（与推荐系统的召回-排序同源）

**大模型做什么**：
- **政策/法规 → 可执行规则**：淘宝 SPU 项目用大模型推导属性类型与品类定义，经小二审核沉淀为正式规则
- **商品理解与归一化**：属性抽取、SPU 对齐、同款聚簇、型号一致性校验
- **难例判定 + 商家可读的拒审理由生成**（Joom 的核心交付）
- **申诉复核与研究辅助**：淘天称每次抽检后 AI 自动总结"哪些判对了、哪些漏了"写回知识库

**小模型做什么**：全量高 QPS 首筛；品牌与侵权匹配（工业上偏好**"比对式"而非"生成品牌名"范式**，以泛化到未见品牌、避免记忆品牌分布过拟合）；重复铺货与同质 SPU 发现；销量/评论异常与团伙关联（抖音识别风险团伙 2.2 万个、处置效率 +45%）

**知识库**：品牌库、资质/认证库（Joom 会因缺证自动冻结商品待补）、违禁品知识图谱、法规条文 RAG

## 6.3 一个稀缺的"小样本微调 + 真实吞吐"双数字

**淘天生鲜凭证审核**（[原文](https://www.53ai.com/news/zhinengyingxiao/2024110149031.html)）【官方】
- 纯 VQA 任务：品种识别 / 商品问题识别 / **问题比例识别**（要数清凭证图里坏了几个鸡蛋）
- **Prompt 工程到瓶颈就上不去了**——无论 GPT-4 还是 Qwen-VL，比例任务卡在"误差 1 个以内准确率 **79%**"，不可上线
- 微调（阿里星云训练 + whale 部署，**A100 训练 14 小时**，epoch=2.2 取最小 eval_loss，用历史数据清洗**免标注**）：**79% → 90% 左右，且标准差收敛**；分类任务 +2pt；问题个数任务相比 GPT-4 **+11pt**
- **压测：双卡 L20、单图、输入输出 token 与微调一致，约 10 QPS**

## 6.4 商品侧真正的瓶颈

**淘宝技术复盘原话**：**"规则变更会反向阻塞已发布商品，需全生命周期回扫"**【官方】

→ 所以商品侧的竞争点正在从"能否识别"转向**"规则变更效率与可解释性"**：政策解析成本、理由质量、申诉闭环速度，而不是模型准确率。

⚠️ 电商侧公开数字口径要小心：Amazon **>99.9%**、**1500 万+ 件**；TikTok Shop **99.5% 上架前检出 / 拦截 7000 万件 / 拒 140 万+ 卖家申请 / 移除约 70 万卖家 / 复杂案最长 24 小时**——**均为平台自述，分母与口径未公开，不可与论文 F1 直接比较**。

# 七、风险面（三个容易被忽略的）

## 7.1 护栏自身就是攻击面

- **AdvJudge-Zero**（[Unit 42](https://unit42.paloaltonetworks.com/fuzzing-ai-judges-security-bypass/)）：自动化 fuzzer 可用**低困惑度的无害 token（markdown 符号、列表标记、结构短语）**操纵 allow/block 的 **logit gap**放行违规内容，**完全黑盒、无需白盒权限**
- **Emoji Attack**（[ICML 2025](https://icml.cc/virtual/2025/poster/45356)）：emoji 插入同样可绕过 Judge LLM
- **WildGuard**反向数据：能把 jailbreak 成功率从 **79.8% 压到 2.4%**
- **MM-SafetyBench**（[arXiv:2311.17600](https://arxiv.org/abs/2311.17600)）：12 个 SOTA 多模态模型即便底座已安全对齐，仍可被**与 query 相关的图像**攻破（5,040 组图文、13 场景）
- **对策**【推断】：输入前规范化（去 emoji/零宽字符/重复标点/结构化模板）+ 判定多模板多种子投票 + 格式异常强制升级人审 + 定期做**护栏指纹红队**

## 7.2 合成标签有系统性偏向

Google 审核全生命周期综述的警告【论文】：**RLHF 模型倾向过度判罚、指令微调模型倾向漏判，且不同 LLM 带可观测的意识形态偏向**。他们用 **3 个 LLM 独立标注 + 多数投票**产出 **48,000+ 条**合成标注，训练出的分类器与专家标注效果相当，但**必须留人工校验集**。（[报道](https://www.helpnetsecurity.com/2026/04/07/google-llm-content-moderation/)）

## 7.3 "判例法"的自举偏差

KuaiMod 的在线 RLUF 负例**全部由线上模型自己采样**，长期可能形成反馈闭环偏差【推断】。论文也没有独立 Limitations 章节。

# 十、易踩的引用陷阱（写博客前必读）

1. **快手"20%" vs "26%/24%"是两个口径**。KuaiMod 论文与官方解读写"举报率降低 20%"（极速版/精选 >20%）；"主站下降超 26%、极速版超 24%"描述的是快手**多模态大模型体系整体**。混用会错。
2. **−20% 的适用范围是"举报 ≥5 次"的高风险候选池**，不是全量内容。
3. **"主站安全算法中心"与"商业化技术部/磁力引擎"是两支团队、两套模型**（前者 YuanQi/KuaiMod/安全大模型，后者明镜 BLM/KwaiBLM/AhaEdit/BLM-Guard），**数字不可互相代用**。
4. **KuaiMod 基座是 YuanQi，不是 Keye**。Keye 报告引用了 KuaiMod、作者重叠，但官方从未声明 Keye 用于审核。把 Keye 榜单分数当"快手审核模型性能"是错误引用。
5. **被广泛误引为快手的 TikTok 论文**：
   - [IPS, arXiv:2412.15251](https://arxiv.org/abs/2412.15251) —— 首页 affiliation 原文为 **TikTok, Inc.**
   - [Embedding-based Retrieval in Multimodal Content Moderation, arXiv:2507.01066](https://arxiv.org/abs/2507.01066) —— 作者组与前者重叠，判断为 TikTok（高置信推断）
6. **KuaiMod 论文里没有"多模态聚类 + 规则挖掘 + codebook + 规则检索召回"**——这套能力在快手安全团队的 AICon 分享里。

# 十二、写作时的几个建议

1. **开篇用"位置变了"而不是"谁被淘汰"**——这是全部证据指向的结论，也最有传播性。
2. **第 2.6 节的双卡推算值得单独成段**：48×4090 只能审 60 万条视频/日，而双卡 L20 能跑 10 QPS 的图片审核——这个 35 倍差距是"小模型必须前置"最硬的论据。
3. **政策注入四选一那张表**（§5.2）适合做成图，是全文信息密度最高的部分。
4. **收尾用岗位跃迁**（规则表达式 → Prompt Engineer → RAG 运营 → 模型教练）+ "部分一线审核员实际上已经被大模型替换掉了"，把技术叙事落到组织变革上。
5. **每个数字都带限定**。这篇素材里最容易被读者挑错的就是快手那组数字，§十那九条陷阱建议在成稿时逐条自查。
