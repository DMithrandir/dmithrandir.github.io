## 〇、先纠正一个前提误区

**❌ 误区**：对抗是"安全的附加题"——把模型训练好、把规则写全，对抗自然就解决了。
**实情**：**对抗不是异常情况，而是治理的常态环境**。

| 视角 | 假设 | 结果 |
|---|---|---|
| **把对抗当异常**| 默认内容是"自然产生"的，违规是"偶发"的 | 规则/模型按"自然分布"优化 → **被主动规避者系统性击穿**|
| **把对抗当常态**| 默认存在**主动优化规避策略的对手**| 按**博弈**设计，把"对手的适应速度"作为设计输入 |

**一手证据（多方独立印证）**：

| 来源 | 表述 |
|---|---|
| 快手安全团队【官方】 | 底线风险**仅占千分之几流量**；对抗变异强（谐音、形近字、**AIGC 低成本生产的风险样本**）；需应对知识规则快速更新与**灾难遗忘**|
| 闲鱼暗语治理（羊城晚报）【媒体】 | **暗语更新堪比"日抛"**，封禁一个几分钟换一套；平台关键词库迭代需数周至数月；"审核逻辑始终是**已知拦截**，而黑产的暗语是**未知变异**" |
| EVADE-Bench【论文】 | 评测 26 个 LLM/VLM，**SOTA 仍频繁误判**|
| AdvJudge-Zero（Unit 42）【论文】 | 判定模型本身可被**低困惑度的无害 token**操纵，**完全黑盒**|

**所以 M6 的核心命题是**：

> **治理的胜负不由"模型的绝对能力"决定，而由"攻防迭代速度的相对差"决定。**
> 这正是 M0 §4b.6 提出的 **Δ（迭代速度差）**概念的攻防侧表述。

## 一、对抗的三类主体与动机

**先分清对手，因为不同对手的规避逻辑完全不同**：

| 类型 | 主体 | 动机 | 规避特征 | 主要战场 |
|---|---|---|---|---|
| **① 变现型黑产**| 有组织团伙 | **直接获利**（导流、诈骗、售假、赌博） | **组织化、工业化、有 ROI 计算**| M8 §2.2、商品治理 |
| **② 规避型内容生产者**| 个人/小团队 | 流量与收益（擦边、低质、标题党） | **试错式、成本敏感**| 内容治理 |
| **③ 攻击型对手**| 竞争对手 / 恶意用户 | 打击对手、消耗资源、报复 | **低成本、高频、针对性强**| M9 举报滥用、M5 申诉滥用 |

**三类对手的差异决定了对策**：

| | 变现型黑产 | 规避型生产者 | 攻击型对手 |
|---|---|---|---|
| **成本敏感度**| 中（有收益支撑） | **高**| **极高**|
| **有效对策**| **提高其变现成本**（断链路、封资金） | **提高其摩擦成本**（限流、加提示） | **识别行为模式 + 限制权益**|
| **单一处置是否有效**| ❌ 无效（换号继续） |  有效（个体惩罚有效） | ⚠️ 部分有效 |

⚠️ **一个关键判断**：
> **对变现型黑产，"封账号"是无效手段**——它的成本极低、可批量补充。**有效的只有"打断变现阶段"**（资金、交易、导流链路）。
> 这解释了为什么快手的处置在**向组织层上移**：团播从"单场断播"升级到**直播权限管控**（累计处置 4600 个低俗团播直播间、**近 100 家公会**）。

## 二、攻击面的全景清单

**治理体系自身就是一个攻击面**——这一点最容易被忽略。按环节列出：

| 环节 | 攻击面 | 攻击手法 | 一手证据 |
|---|---|---|---|
| **M0 发现**| 信号污染 | 用大量噪声举报掩盖真实问题 / 制造假热点 | — |
| **M1 规则**| 规则探测 | 通过反复试探推断规则边界 | 闲鱼"日抛暗语"即规则探测的产物 |
| **M2 模型**| **判定模型本身**| **低困惑度 token 操纵 logit gap**| **AdvJudge-Zero（Unit 42）**：markdown 符号、列表标记、结构短语即可操纵 allow/block，**完全黑盒**|
| **M2 模型**| 多模态绕过 | 与 query 相关的图像攻破安全对齐 | **MM-SafetyBench**：12 个 SOTA 多模态模型被攻破（5,040 组图文、13 场景） |
| **M2 模型**| Emoji 注入 | 插入 emoji 绕过 Judge LLM | **Emoji Attack（ICML 2025）**|
| **M2 模型**| 护栏指纹识别 | 先识别用的是哪套护栏，再针对性攻击 | **Peering Behind the Shield（arXiv:2502.01241）**|
| **M3 召回**| 规避召回信号 | 控制曝光、避开高消费时段、控制发布节奏 | 闲鱼案例：正常用户行为的"反面"即黑产特征 |
| **M3 人审**| 疲劳攻击 | 用大量边缘内容消耗审核产能 | 人力上限是硬约束（M3 §2.5） |
| **M9 举报**| 举报武器化 | 批量举报竞品，消耗审核资源并致其内容停推 | M9 §五 |
| **M5 申诉**| 申诉滥用 | 模板化申诉、试探规则边界 | M5 §4.3 |
| **全链路**| 规模化攻击 | 僵尸账号批量开播/发布 | 快手 2025-12-22 直播黑产事件（第三方称超 1.7 万账号同时开播） |

⚠️ **最需要记住的一条**：
> **判定模型本身就是一个可攻击对象。**多数团队只防"内容绕过审核"，不防"审核器被操纵"。
> AdvJudge-Zero 的可怕之处是**它不需要白盒权限**——用结构化的无害文本就能移动判定边界。

## 三、四类对抗手法与对策

### 3.1 文本变形类

| 手法 | 例子 | 对策（**按 M0 §4b.6 的 Δ 决定投入**） |
|---|---|---|
| 谐音 / 形近字 | 快手的"谐音字、形近字" | **输入规范化 + 同义/音近/形近词库**（快手 Advanced RAG 的前置模块正是如此） |
| 分词 / 拆分 | 把词拆开规避词典 | Trie 匹配 + 上下文语义 |
| 委婉语 / 暗语 | **闲鱼「二手空调」「捷安特」「苹果卡针」**| ⚠️ **词库路线必输**（Δ 极大）→ 转向**行为模式识别**|
| Emoji / 零宽字符 / 重复标点 | 插 emoji、零宽字符 | **输入规范化**（去 emoji、零宽字符、重复标点） |
| 结构化模板 | markdown 符号、列表标记 | **规范化 + 格式异常强制升级人审**（M2 §8.2） |

### 3.2 多模态对抗类

| 手法 | 说明 | 对策 |
|---|---|---|
| **图像相关性攻击**| 用与 query 相关的图像攻破安全对齐 | MM-SafetyBench 的警示：**底座对齐 ≠ 组合安全**|
| **跨模态漂移**| 字幕与语音不一致（字幕写安全内容，语音说违规内容） | 快手 **BLM-Guard**专门建模"**字幕-语音漂移**"这类跨模态不匹配 |
| **单帧正常、组合违规**| 昏暗场景 + "招聘/工资"文字 = 色情招嫖联想 | 快手安全团队明确将"**多维度信息组合违规证据**"列为长链推理核心场景 |
| **AIGC 低成本风险样本**| 用生成模型批量产出违规内容 | 检测 + **内容凭证（C2PA/水印）+ 平台标识 + 传播侧限流**组合治理 |

⚠️ **跨模态一致性的正面用法**：既然"字幕 vs ASR vs 画面 OCR"的矛盾是攻击特征，那它同时也是**检测信号**——**把相互矛盾当作高风险信号，直接触发人审**。

### 3.3 行为与组织类

| 手法 | 特征 | 对策 |
|---|---|---|
| **批量账号**| 同时开播、批量上架、集中回复 | 群体行为识别（**图计算**） |
| **矩阵化运营**| 多账号互相引流、分工明确 | **关系图谱**：单账号可伪装，**关系结构难伪装**|
| **跨域导流**| 站内展示、站外成交（规避平台治理） | 拦截载体：**二维码、短链接**（闲鱼已开始用 AI 语义识别） |
| **节奏控制**| 避开审核高峰、利用深夜时段 | 时序特征建模（"**深夜集中回复陌生账号**"即闲鱼点名的异常） |

### 3.4 攻击判定器类（最被低估）

| 手法 | 对策 |
|---|---|
| 用无害 token 操纵判定边界 | ① **输入规范化**；② **多模板 × 多种子投票**；③ **判定结果一致性检查**|
| 识别护栏指纹后针对性攻击 | ① **不暴露护栏类型**；② 定期做**护栏指纹红队**（AP-Test 类方法） |
| 试探规则边界 | ① **不透传过细的判定依据**（M5 §2.5）；② 监控"同主体高频试探" |

**正向对照（证明防御有效）**：**WildGuard 把 jailbreak 成功率从 79.8% 压到 2.4%**。

## 四、防御体系的结构：四层纵深

```
┌──────────────────────────────────────────────────────────┐
│ L1 提高规避成本（最有效、最少被用）                        │
│   · 打断变现阶段：资金、交易、导流链路                     │
│   · 抬高账号获取成本：注册风控、设备指纹                   │
│   · 处置上移到组织层：账号 → 权限 → 公会/团伙              │
├──────────────────────────────────────────────────────────┤
│ L2 输入规范化（最便宜、最该先做）                          │
│   · 去 emoji / 零宽字符 / 重复标点；剥离结构化模板          │
│   · 同义 / 音近 / 形近词库                                │
├──────────────────────────────────────────────────────────┤
│ L3 判定层韧性                                              │
│   · 多模板 × 多种子投票；格式异常强制升级人审               │
│   · 多信号交叉（语义 + 行为 + 关系 + 情绪 + 时序）          │
├──────────────────────────────────────────────────────────┤
│ L4 感知与迭代（决定长期胜负）                              │
│   · 对抗样本库；红队；误判复盘自主迭代                      │
│   · 关系图谱 / 图计算                                     │
└──────────────────────────────────────────────────────────┘
```

⚠️ **L1 为什么排在最高优先级，却最少被用**：
> 因为它**不是算法问题，是业务与法务问题**（涉及资金链路、账号体系、公会管理）。算法团队无法单独完成，所以最容易被跳过。
> 但**它才是唯一能改变攻防成本结构的一层**——L2/L3 只是提高单次规避成本，**L1 提高的是对手的进入成本**。

**抖音反网暴的 L4 实现值得单列**（M0 §4b.1）：
> **AI 全天候复盘误判案例，自主学习新的网暴手段**——把"误判"变成感知能力的输入，**这就是 L4 从"人工维护规则"升级为"自动迭代"的形态**。

## 五、红队机制：把对抗变成例行工作

**没有红队的组织，只能等黑产来当红队。**

| 维度 | 设计 |
|---|---|
| **红队目标**| ① 找绕过路径；② 做**护栏指纹识别**；③ 测**判定器可操纵性**|
| **频率**| 常规类目按月；底线类目按周；新规则上线必测 |
| **产出**| 对抗样本库、防御缺口清单、规则/模型修订提案 |
| **与 M0 的关系**| **红队是"主动发现"的一种**——它把发现时延从"等黑产出现"压到"上线前" |

**红队的三个必备测试项**：

| 测试 | 检查什么 |
|---|---|
| **结构化模板测试**| 在正常内容中插入 markdown 符号/列表标记，看判定是否漂移（AdvJudge-Zero 的手法） |
| **跨模态矛盾测试**| 字幕/语音/画面 OCR 相互矛盾，看是否被识别为高风险 |
| **同主体高频测试**| 同一账号短时间内大量相似申诉/举报，看是否被识别（M5 §4.3、M9 §五） |

## 六、对抗样本库：把攻击变成资产

**对抗样本库与判例库、谣言库是同一种思路：结论复用让能力随治理量增长。**

| 库 | 内容 | 用途 |
|---|---|---|
| **对抗样本库**| 已确认的绕过样本 + 变形手法 | 回归测试、模型评测、规则验证 |
| **负向判例库**| "为什么不违规"的案例 | 防误伤（M5 §2.7） |
| **判例库 / 谣言库**| 已确认的判定 + 理由 | 感知加速（M0 §4b.4） |

⚠️ **对抗样本库的一个硬要求**：**必须在每次模型/规则变更后做回归**。否则会出现"修好 A 绕过、弄坏 B"的隐性退化——这是对抗场景下最常见的质量事故。

## 七、攻防节奏：时效是一等指标

**M8 已指出：直播"不可回扫"，所以直播的全部希望压在事中时效上。**对抗侧同理：

| 环节 | 时效要求 | 一手证据 |
|---|---|---|
| **识别**| 分钟级 → **秒级**| 快手直播【官方】 |
| **判定生效**| 新规则上线到全量 | M4 §四 的三段时效 |
| **人审纠错回流**| **约 10 分钟**（相同物料 MD5 命中即改判） | 腾讯云文档【官方】 |
| **规模化攻击的响应**| 全链路截断时间 | 快手 2025-12-22 事件（第三方称约 2 小时）⚠️**非官方口径**|

⚠️ **一次负面对照值得记录**：2025-12-22 快手直播遭黑产规模化攻击，第三方技术社区称"超 1.7 万个僵尸账号同时开播"、约 2 小时后全平台截断直播。
**该事件与"审核链路能否承载并发"的因果联系无任何官方说明**——引用时只能作为并列事实，**不能写成因果**。

**可以提炼的通用教训（不指向具体事件）**：
> **治理体系的容量必须按"攻击峰值"设计，而不是按"日常均值"设计。**
> 这与 M2 §〇 的结论是同一条：**吞吐是硬约束**——日常 6.81 QPS 的集群，遇到 1.7 万账号同时开播时，瓶颈不在模型准确率而在**并发容量**。

## 八、对抗体系的校验三维度

| 维度 | 核心指标 | 过程指标 |
|---|---|---|
| **韧性**| **对抗样本集上的召回**（单独出报表，不混入总体召回） | 各已知手法的绕过率、新手法发现时延 |
| **发现速度**| **Δ（迭代速度差）**、新变体从出现到感知的时延 | 红队发现的缺口数、对抗样本库增量 |
| **成本结构**| **对手的单位规避成本是否上升**| L1 手段的使用率（资金/账号/组织层处置占比） |

⚠️ **第一条里最关键的是"单独出报表"**：
> **对抗样本的召回绝不能混进总体召回率**——否则会被大量常规样本平均掉，**掩盖真实退化**。

⚠️ **第三条是本篇最独特、也最少被统计的指标**：
> 常规指标衡量的是"**我们抓到了多少**"，而它衡量的是"**对手要花多少成本才能绕过**"。
> **只有后者才反映攻防态势的长期走向**——抓得多但对手成本在下降，说明防线在恶化。

## 九、常见反模式（自查表）

| 反模式 | 表现 | 根因 | 修法 |
|---|---|---|---|
| **把对抗当异常**| 规则按自然分布优化 | 未把对手当设计输入 | 按博弈设计（§〇） |
| **只防内容绕过，不防判定器被操纵**| 无人测 logit gap 漂移 | 未把判定器视为攻击面 | 红队加结构化模板测试（§五） |
| **对黑产只封账号**| 换号继续 | 处置粒度错配 | 处置上移到权限/组织层（§一） |
| **对抗召回混入总召回**| 总体指标好看，实际退化 | 未分口径 | **单独出报表**（§八） |
| **对抗样本库不回归**| 修 A 坏 B | 缺回归机制 | 每次变更后回归（§六） |
| **只用语义对抗语义**| 词库迭代追不上日抛暗语 | 忽略 Δ | 量 Δ 再选路径（M0 §4b.6） |
| **容量按均值设计**| 遇规模化攻击即失守 | 未按峰值设计 | 按攻击峰值规划（§七） |
| **无红队**| 等黑产来当红队 | 缺例行机制 | 建红队与测试项（§五） |
