## 〇、先纠正一个前提误区

**❌ 误区**：策略的价值是"用更聪明的模型把准确率做上去"。
**实情**：策略的价值是**在约束下做最优的决策分配**。约束有三个，而且都是硬的：

| 约束 | 一手证据 | 含义 |
|---|---|---|
| **算力吞吐**| 快手 KuaiMod：**48×RTX4090 / QPS 6.81 / 日均 60 万条**；阿里云文档：视频大模型审核默认 **10 路并发**、直播 **5 路**| 大模型审核的**吞吐是稀缺资源**|
| **单件成本**| Joom 的目标：日处理 2 万 → 200 万件且**成本持平**；TikTok 级联把算力压到全量直推的 **1.5%**| 成本必须随量级下降，否则规模不成立 |
| **误伤上限**| SIRF："真实部署约束不是平均准确率，而是在高精度与秒级延迟下能自动处理多少风险" | 误伤是硬上限，不是可以拿精度换的东西 |

**"吞吐是稀缺资源"这个判断有多硬？**用两个真实数据算一下：

- 快手 KuaiMod：6.81 QPS × 86,400 s ≈ **588,000 条/日**，而论文写的日均审核量是 **600,000 条/日**—— **几乎卡着 100% 利用率设计，没有冗余**
- 摊到单卡：6.81 ÷ 48 ≈ **0.142 QPS/卡**，即**单张 4090 判一条视频约需 7 秒**
- 对照淘天生鲜的商品审核（单图 VQA）：**双卡 L20 约 10 QPS**（单卡 5 QPS，约 0.2 秒/条）

→ **视频级多帧 VLM 判定与单图 VQA 判定之间约 35 倍吞吐差。**大模型视频审核不是"贵一点"，而是**比图片审核贵一到两个数量级**。所以"前置小模型"不是优化项，是**前提**。

**一句话定义策略的价值**：

> **Strategy 的唯一职责，是用最小的代价精确实现 Policy 的意图。**
> 它不决定"什么算问题"（那是 Policy），它决定"**在资源约束下，哪些内容交给谁判、用什么阈值、误伤多少**"。

## 一、策略在链路中的位置与输入输出

```
M1 Policy 交付                         M2 Strategy 交付
─────────────────                     ─────────────────
问题定义 / 标签体系                    机审模型 + 多标签头
标准文本 + case          ──────────→   阈值集（按风险类）
处置建议（阻断/限流/标注）              级联路由 + 分流比
机审可判定性说明             ──────→   回扫任务
指标口径                               处置动作编排
                                      监控与漂移触发
```

### 1.1 三个必须提前问清的问题（否则一定会返工）

| 问题 | 为什么重要 | 谁来回答 |
|---|---|---|
| **每条规则对应什么证据？**| 决定这个类目该用图、用文、还是用行为序列 | Policy |
| **误伤上限是多少？**| 决定阈值锚点，这个数不给，阈值只能拍脑袋 | 业务 + Policy |
| **处置动作是什么？**| 决定输出形态（要概率还是要理由？要不要定位？） | Policy + 产品 |

⚠️ **第三个问题最常被漏**。Joom 的关键设计就是**不做 Yes/No，而输出结构化定位标签**（"商标侵权在第 5 张商品图"）——因为它的下游是商家工单，需要理由。**输出形态由处置动作倒推，不是由模型能力决定。**

### 1.2 策略的四个子问题

| 子问题 | 核心权衡 | 本篇对应章节 |
|---|---|---|
| **怎么分工**| 谁判全量、谁判难例 | §二 |
| **怎么编译**| 规则注入到哪个位置 | §三 |
| **怎么定阈值**| 召回与精度的分配 | §四 |
| **怎么上线与回扫**| 灰度、回滚、存量处理 | §五 |

## 二、大小模型分工：级联是事实标准

### 2.1 四类路由策略对比

| 类型 | 做法 | 代表案例 | 数字 |
|---|---|---|---|
| **前置拦截**| 轻量模型先滤掉"确定安全"，其余送大模型 | 快手磁力引擎 | **拦截过滤逾 80% 常规案例**|
| **级联路由**| 轻量 router 筛高风险 → MLLM 细判 | TikTok [Filter-And-Refine](https://aclanthology.org/2025.acl-industry.62/) | **F1 +66.5%**（仅 2% 微调数据）、自动审核量 **+41%**、算力 **1.5%**|
| **置信度门控**| 二级仅在置信不足时唤醒 | [Joom 官方复盘](https://about.joom.com/blog/3cea9966b0b28081b4c6df776b6d3435) | 日处理 **2 万 → 200 万件（100×）**、**成本持平**|
| **多级动态推理**| 按 case 难度动态选择算力 | 网易易盾（QCon 提纲） | 用少算力处理简单 case，复杂 case 用重计算 |
| **判例兜底**| Lite 模型全量执法 + RAG 检索判例 | 字节 [UNIVID](https://arxiv.org/html/2606.05748v1) | 漏放 **−42.7%**、误伤 **−37.0%**、替换 **1,000+ 个**政策专用小模型模块 |

### 2.2 通用形态：三级级联

```
┌──────────────────────────────────────────────────────────┐
│ L0 规则层：词典 / Trie / 正则 / 字符规范化 / 图谱匹配       │
│   —— 拦低成本规避与确定黑白；成本≈0                        │
├──────────────────────────────────────────────────────────┤
│ L1 轻量判定：0.6B~8B 多标签头 / 判别式模型                  │
│   —— 全量高 QPS 召回，输出多风险概率                       │
├──────────────────────────────────────────────────────────┤
│ L2 精判：大模型 / VLM / 判例 RAG                           │
│   —— 只接 L1 置信不足的难例；给理由与定位                  │
├──────────────────────────────────────────────────────────┤
│ L3 人审：只接「高不确定 + 高影响 + 格式异常」               │
└──────────────────────────────────────────────────────────┘
```

**L3 的准入条件值得单列**（不是"L2 不确定就给人审"，那样人审会被淹没）：
- **高不确定**：模型置信度落在灰区
- **高影响**：内容曝光量大、创作者/商家影响大、涉及底线类
- **格式异常**：输入含结构化模板、零宽字符、emoji 密集、被识别为对抗样本（见 §八）

### 2.3 ⚠️ 关键坑：缺失标签不能当负样本

[RADAR（ACL 2026 Industry）](https://aclanthology.org/2026.acl-industry.139/) 实测：**把"跨标注管线割裂导致的缺失标签"当作负样本，会让 0.5B 骨干的 R@P60 直接掉 18.42 分（43.77→62.19）**。

**这是工业级路由最大的隐性偏差**，而且极难自查——因为数据看起来"有标签"，只是标签是"未标注"而不是"已确认为安全"。**修法**：显式区分"已确认为正 / 已确认为负 / 未标注"三态，训练时对未标注样本做掩码（Validity-Aware Masking）。

### 2.4 蒸馏：学生能反超教师，但要防「对齐税」

**收益侧**（算法可以比数据更好）：
- RADAR：用 Qwen3-VL-8B 逐风险类做教师、KL 蒸馏进 0.5B~4B 学生路由，**蒸馏后的 4B 学生在风险检出与流量削减上双双超过未蒸馏版本，甚至超过教师专家**——因为蒸馏同时补偿了跨标注管线造成的监督缺口
- 快手磁力引擎：**7B 对标开源 32B/72B 级别，年度节约千万量级**
- 快手磁力引擎：蒸馏后轻量学生模型"以极低算力开销**对齐大模型 70%–80%**的核心能力"

**风险侧（必须一起讲）**：[COGNIT-Guard](https://arxiv.org/abs/2609.33671) 测出了小模型的**对齐税（alignment tax）**——
> Laya-322M 域外性能从 **60.33% 掉到 56.81%**（域内微调的 CLM-8B 只有 55.10%）；用 **experience replay 回放**才把 OOD 恢复到 **64.10%–65.05%**，同时域内保持 99.67%–99.84%。

**这与治理场景的对抗性直接冲突**：内容治理的对抗变异（谐音、形近字、AIGC 新样本）**恰恰全是域外的**。所以：
- ❌ 只看域内 gold set 就上线
-  **必须配 experience replay 或持续回流**，否则新风险一来就集体失效

### 2.5 蒸馏的两条路线怎么选（快手安全团队的方法论）

| 框架 | 蒸馏方式 | 适用任务 | 原因 |
|---|---|---|---|
| **生成式框架**| 黑盒 / response-level | 需要**保留推理能力**的任务 | 学的是输出与推理过程 |
| **判别式框架**| 白盒 / logits、feature-level（支持中间层连续数值输出） | **离散型预测（分类、打标）**| **性价比更好**|

再叠加"**数据蒸馏 + GRPO**"（受 DeepSeek-R1 启发）：用大模型生产推理过程数据做 SFT 冷启动，再叠强化学习进一步提升推理与决策能力。

## 三、规则编译：规则住在哪里（Policy 决策的工程落地）

> M1 §七 已给出决策依据（**变更频率 × 证据具体程度**），本节讲工程侧怎么实现。

### 3.1 四种注入位置的工程对比

| 位置 | 实现 | 变更时延 | 延迟影响 | 工程复杂度 |
|---|---|---|---|---|
| **Prompt**| 政策规则写进 system prompt | 秒级 | 高（吃上下文） | 低 |
| **检索库**| 政策/判例向量化，推理时检索 | 热修复 | 中（检索开销累积） | 中 |
| **模型权重**| CPT / SFT / LoRA | 需重训（小时~天） | **低（verdict-only）**| 高 |
| **判例库**| 人工标注判例结构化后 in-context | **天级**| 中（上下文变长） | 中 |

### 3.2 一手证据：两条路线的实测取舍

**路线 A：政策烧进权重（SIRF，小红书，EMNLP 2026 Industry）**
- **明确否定推理期注入政策**——理由是**长上下文/RAG 延迟不可接受**
- 做法：用 EntiGraph + MAGA 改写 + 账号级 CoT **零人工标注**合成政策语料，约 **70M CPT tokens**继续预训练，部署为 **verdict-only**（只出标签，4–5 token）
- **同源对照设计**（这点最值得学）：Qwen3-8B-SFT vs SIRF-8B-SFT，政策注入方式与输出形式完全相同，**唯一差异是有无 policy-grounded CPT**
- 结果：**Black Recall@P95 56.2% → 71.3%（+15.1pp）**；作树模型裁决层**多找回 20% 误罚样本**；跨域**误罚 −70%**；**QPS +14~23%**；最大并发 **381→436**；延迟在并发 16/32/100 下 **−8.8%/ −12.6%/ −18.2%**

**路线 B：政策进 Prompt + 层级路径预测（Hi-Guard，小红书，KDD 2026）**
- 规则直接写进 Prompt，用 **GRPO + 多级软边界奖励**（判错到"兄弟类别"轻罚、跨域重罚）
- 零样本泛化集总体准确率 **+12.13%**、P **+14.02%**、R **+10.28%**；消融显示**规则结构化注入贡献最大**

⚠️ **这两篇不是路线之争，而是分层共存**（同一团队）：Hi-Guard 管"**判到哪一类**"（政策可改性），SIRF 管"**低成本高并发执行**"（执行成本）。

**判例库路线（UNIVID，字节，ACL 2026）**：从 **10 万条人工标注违规事件**的知识库检索判例做 in-context 判断，判例由 Gemini-2.5-Pro 把人工标注**结构化为"政策条目 + 违规理由"**入库。

### 3.3 策略侧要实现的东西（不只是选位置）

无论选哪条路线，策略都要交付这四样：

| 交付项 | 内容 | 关联 Policy 产出 |
|---|---|---|
| **标签 → 检查项编译**| 层级标签转成可判定条件 | 标签体系 |
| **语义表示**| 标签的自然语言描述 + 向量表示 | 标签命名与描述质量（**这是技术资产**） |
| **理由生成**| 输出违规定位 + 规则条款引用 | 处置动作（是否需要商家/创作者可读理由） |
| **冲突校验**| 标签-规则条款自动匹配与冲突检测 | 规则一致性 |

**"语义热插拔"是这条路线的最大红利**（快手安全大模型开集 Tagging）：把 one-hot/multi-hot 稀疏标签转成**自然语言描述的稠密向量**，**新类别只需一条文本描述即可零样本扩展、无需重训**。
→ **它对策略的含义**：新风险的上线瓶颈从"训练周期"变成"**Policy 写清楚一条描述**"。

## 四、阈值标定

### 4.1 三条原则

1. **按风险类分别标定，不要全局一个阈值**。RADAR 的线上数据显示**正例率在不同风险类之间差异极大**（虚假互动 **9.0%**vs 低质内容 **25.5%**）——同一个阈值在不同基础率下的误伤/漏放表现完全不同
2. **在约束下优化，而不是优化裸指标**。审核场景的正确形式是：
   - **给定精度锚点，最大化召回/旁路率**：RADAR 提出 **APR@R90/R95**（守住 90%/95% 召回下最大化流量旁路率）与 **R@P60**（精度锚定 60% 下的召回）
   - 对照 SIRF 的表述："_在高精度与秒级延迟下能自动处理多少风险_"
3. **阈值必须可用线上数据回溯校准**。用分层 gold set 定期重标，而不是定一次用半年

### 4.2 一个必须先解决的前置问题：置信度必须先校准

**不同模型的原始置信度不可比**——这是级联能不能设统一阈值的**前置条件**。

[CAUC（Calibration-Aware Uncertainty Cascades）](https://arxiv.org/abs/2609.11446) 的做法：**独立校准每个模型的置信度**，建立共同可靠性尺度，统一回答三个决策："接受早停 / 升级强模型 / 融合输出"。
- 六语言基准：相对"只用强模型"**平均相对精度 +1.9%**，同时**省掉约 47% 的强模型调用**
- 图像分类：预测性能持平或更好，**GFLOPs 最多降 57%**
- 理论结论：**校准给置信度阈值一个显式的 selective-risk 解释，而未校准分数没有可比的可靠性保证**

→ **校准本身就是收益，不是额外成本。**这是策略侧性价比最高的一项投入。

### 4.3 离线评测指标怎么设（不要只看 F1）

| 指标 | 衡量什么 | 什么时候用 |
|---|---|---|
| **R@P（固定精度下的召回）**| 误伤约束下能抓多少 | **上线决策的主指标**|
| **APR@R90/R95**| 召回约束下的流量旁路率 | 级联路由的容量规划 |
| **PR-AUC**| 整体排序质量 | 模型选型（RADAR：Qwen3-VL-2B→4B 使 PR-AUC **68.16→70.38**） |
| **ECE / Brier**| 置信度是否可信 | 阈值标定的前置校验（COGNIT-Guard：**ECE 1.12%**、Brier 0.0104） |
| **误伤率（分风险类）**| 用户体验与成本 | 必须与漏放率**并列报告**|

**生产级参考水位**（[arXiv:2512.03553](https://arxiv.org/abs/2512.03553)，已上线 + 大 A/B 的直播审核系统）：
- 分类管线：**67% recall @ 80% precision**（打已知违规）
- 相似度检索管线：**76% recall @ 80% precision**（打新颖/隐性违规）
- **MLLM 只当蒸馏教师，不做线上判定器**
- 大 A/B：**不良直播的用户观看量下降 6~8%**

→ 两个有意思的推论：
1. **在 80% 精度约束下，生产级审核召回大致在 70% 上下**——这比"92.4% 准确率"这种数字更有可比性
2. **"新颖/隐性违规"靠检索管线召回反而更高**（76% > 67%）→ 支持"判例库检索"优于"扩标签再训分类头"

## 五、上线流程与回扫

### 5.1 五步上线（缺任何一步都是事故来源）

| 步骤 | 做什么 | 关键检查 |
|---|---|---|
| **1 离线评测**| 分层 gold set，**按风险类报告 R@P**| 不看裸 F1；看最差类目 |
| **2 影子模式**| 只判定不处置，与线上策略对比 | **测真实召回与漏放**（离线测不出） |
| **3 小流量灰度**| 1~5% 流量，观测生态指标 | 双审一致率、申诉率、误伤率 |
| **4 逐步放量**| 而非一次性切流 | Joom 明确采用**灰度放量**|
| **5 监控与回滚**| 模型/提示词/阈值/策略都要**版本化可回滚**| 出事时"回滚"要能一键完成 |

⚠️ **Gap 提示**：**离线指标与线上生态指标之间的鸿沟是全链路最大的 gap**。离线 R@P 提升不等于举报率下降——中间隔着分流比、曝光结构、用户构成。**必须用影子模式 + 灰度来桥接，靠离线调参是过不去的。**

### 5.2 回扫：最容易被漏、成本最高的一环

| 治理域 | 回扫要求 | 证据 |
|---|---|---|
| **商品**| **规则变更会反向阻塞已发布商品，需全生命周期回扫**| 淘宝技术复盘【官方】 |
| **内容**| 老内容违规需定期回扫（尤其新规上线后） | KuaiMod 把判定嵌入推荐特征，本质是持续作用 |
| **直播**| 实时流无法回扫，只能靠时效，需**秒级**| 快手："识别时效从分钟级降至秒级" |

**回扫的策略设计要点**：
- **分级回扫**：高风险类目/高曝光内容优先，长尾降频
- **算力预算**：回扫会占用与大模型同源的算力，必须和日常审核共享预算规划
- **指标扰动预警**：回扫上线会让生态指标突变（`低质 VV 占比` 突然改善或误伤率突然上升），**指标口径必须标注是否含回扫**（M1 §五 口径五项要素）

### 5.3 一个常被忽略的极短回流链路

**腾讯的纠错名单机制**【官方文档】：机审纠错 → **MD5 完全相同的物料再送审即按纠错后标签输出，约 10 分钟生效**（可按 Biztype 限定生效策略）。

→ **成本极低、收益明确**：相同物料（尤其是商品图的复用、视频的重复上传）不需要重复判断。策略侧应把"**物料指纹 + 纠错覆盖**"做成一等公民。

## 六、成本工程

### 6.1 杠杆按性价比排序（审核场景实测）

| 优先级 | 手段 | 实测收益 | 备注 |
|---|---|---|---|
| **1**| **级联路由 / 前置过滤**| 拦截 **>80%**常规案例；算力降至全量直推的 **1.5%**| 数量级收益，最高优先 |
| **2**| **批处理**| 审核多为极短输出，批处理收益直接 | 基础项 |
| **3**| **静态 FP8 量化**| **+26.7% TPS、TTFT −20.4%、TPOT −32.4%**| vLLM 官方实测 |
| **4**| **蒸馏 + 小模型替换**| 7B 对标 32B/72B，**年度节约千万量级**| 周期长但收益大 |
| **5**| **Multi-LoRA**（多业务线共底座） | S-LoRA 单卡服务**数千 adapter**、吞吐**最高 4×**| 适合"同底座 + 每业务线一 adapter" |
| **6**| **投机解码**| 公开实测 1.18x（vLLM 批处理）~ 3x（TPU） | **审核场景收益有限**（输出极短），优先级最低 |

### 6.2 ⚠️ 一个反直觉的量化坑

**vLLM 官方实测**（[GPUStack 基准文档](https://github.com/gpustack/gpustack/blob/main/docs/performance-lab/references/the-impact-of-quantization-on-vllm-inference-performance.md)）：

> **显存不紧张时，纯 weight-only 量化（INT4）因反量化开销导致 TPS/TTFT/TPOT 全面退化。**

-  该用：**静态 FP8**（大收益）、**AWQ/GPTQ**（weight-only 里最优）
- ❌ 别用：bitsandbytes / GGUF（表现差）、**显存充足时的纯 weight-only INT4**
- 质量代价参考：INT4-AWQ 在 Qwen3-8B 上 CEVAL 79.27→76.15、MMLU 74.78→73.59
- KV cache 量化**收益有限**

**快手商业化风控的对照做法**：**AWQ 量化把 13B 权重从 26.2G 压到 7.25G**（量化前对权重做常量缩放 + **保护 1% 显著权重**），配 vLLM/PagedAttention。

### 6.3 引擎选型

| 模型类型 | 引擎 | 量化 | 理由 |
|---|---|---|---|
| 生成式小 LLM（0.5B~4B） | vLLM / SGLang / TensorRT-LLM | **FP8**| 生态成熟、批处理好 |
| **判别式 / 双向模型**（BERT、DeBERTa、直接判定头） | **ONNX Runtime / OpenVINO / TensorRT**| **INT8 静态**| **CPU 即可，最省钱**，易多实例扩展 |

一手参照：COGNIT-Guard 的 **322M 双向直接判定模型**（Laya-322M）在 Ascend 910C 上**纯 NPU 21.77ms / 45.90 QPS**；线上串行 **CPU 门控 + NPU**级联 41.63ms（P50 39.47ms，准确率 99.23%，**FPR 0.00%**）。

### 6.4 输出长度也是成本杠杆

**SIRF 把部署形态改成 verdict-only（4–5 token）**，这是"政策进权重 + 只出标签"的组合收益：既省解码时间又省校准成本。

同类杠杆：**Keye-VL 单图视觉 token 可在 4–20480 之间调**（模型卡）——这是视频/图像审核最直接的成本旋钮。
**视频降维路径**：镜头切分/关键帧抽取 → 音频轨 ASR → 字幕与画面 OCR → 压成"**文本 + 少量关键帧**"，让**文本小模型承担主要判定负载**（快手 KuaiMod 的五状态转移里"依次排查描述/标题/OCR/ASR"就是这个范式）。

## 七、策略合理性校验（三维度框架）

> 与 M1 Policy 篇的三维度完全平行。**策略的价值在于把 Policy 的意图精确落地**，所以验收也分三个维度。

### 7.1 维度一：召回完备性（对应"意图不漏"）

| 层次 | 指标 | 说明 |
|---|---|---|
| **核心**| **分类目漏放率**| 必须分风险类，不能只看总体 |
| **核心**| **违规曝光率（VVR）**| 最接近生态结果的指标 |
| **过程**| **影子模式的召回**| 唯一能测"真实漏放"的手段 |
| **过程**| **未覆盖样本池**| 与 M1 共享的先行指标 |

### 7.2 维度二：精度与误伤（对应"不伤无辜"）

| 层次 | 指标 | 说明 |
|---|---|---|
| **核心**| **误伤率（分类目）**| 必须与漏放率**并列报告**|
| **核心**| **申诉成功率**| 误伤的最终裁决信号 |
| **过程**| **双审一致率**（策略会放大规则歧义） | 与 M1 共享 |
| **过程**| **跨域误伤**| SIRF 作裁决层**跨域误罚 −70%**是标杆 |

**离线看 R@P，线上看漏放率 + 误伤率 + 申诉率。**

### 7.3 维度三：成本与延迟（对应"约束内"）

| 层次 | 指标 | 说明 |
|---|---|---|
| **核心**| **单件判定成本**| 必须按量级算总账：`单件成本 × 日量级` 决定自动化天花板 |
| **核心**| **大模型调用占比 / 分流比**| 决定成本能否随量级下降 |
| **核心**| **SLA（P50/P99 判定延迟）**| 直播场景尤其硬（快手：分钟级 → 秒级） |
| **过程**| 峰值 QPS 承载、算力利用率、回扫预算占用 | 容量规划 |

⚠️ **这一维度最容易被忽略，却直接决定方案可行性**：
> 阿里云文档给的容量红线是"视频大模型审核默认 **10 路并发**、直播 **5 路**"。如果方案的算力只够跑 10 QPS，那么 **99%+ 的内容根本走不了大模型路径——准确率再高也没有意义**。

### 7.4 速查

| 维度 | 验收指标 | 与 M1 的接口 |
|---|---|---|
| 召回完备性 | 分类目漏放率、VVR、影子模式召回 | 共用"未覆盖样本池" |
| 精度与误伤 | 分类目误伤率、申诉成功率、跨域误伤 | 共用"误伤率必须与漏放并列"原则 |
| 成本与延迟 | 单件成本、分流比、SLA、峰值承载 | 成本侧让 M1 的"成本维度"可核算 |

## 八、对抗鲁棒性（策略侧必须自建的能力）

> M1 管"规则层级清晰度"，M2 管"判定链路的韧性"。两者缺一不可。

### 8.1 护栏自身就是攻击面

- **AdvJudge-Zero**（[Unit 42](https://unit42.paloaltonetworks.com/fuzzing-ai-judges-security-bypass/)）：自动化 fuzzer 用**低困惑度的无害 token**（markdown 符号、列表标记、结构短语）操纵 allow/block 的 **logit gap**放行违规内容，**完全黑盒、无需白盒权限**
- **Emoji Attack**（[ICML 2025](https://icml.cc/virtual/2025/poster/45356)）：emoji 插入同样可绕过 Judge LLM
- **MM-SafetyBench**（[arXiv:2311.17600](https://arxiv.org/abs/2311.17600)）：12 个 SOTA 多模态模型即便底座已安全对齐，仍可被**与 query 相关的图像**攻破（5,040 组图文、13 场景）
- **护栏指纹可被识别**：[Peering Behind the Shield, arXiv:2502.01241](https://arxiv.org/abs/2502.01241)
- **正向对照**：WildGuard 把 jailbreak 成功率从 **79.8% 压到 2.4%**

### 8.2 防御清单

| 层 | 措施 |
|---|---|
| **输入规范化**| 去 emoji、零宽字符、重复标点；剥离结构化模板；同义/音近/形近词词库（**快手安全大模型的 Advanced RAG 前置模块就是这么做的**） |
| **判定稳定性**| 多模板 × 多种子投票；判定结果一致性检查 |
| **升级机制**| **格式异常样本强制升级人审**（而不是让模型硬判） |
| **红队**| 定期用 AP-Test 类方法做**护栏指纹红队**；维护对抗样本库 |
| **性能对照**| 对抗样本上的召回单独出报表（不要混在总体召回里被平均掉） |

### 8.3 监控与漂移：

| 层 | 触发条件 | 动作 |
|---|---|---|
| **统计层**| 输入/判定分布 PSI、KL 超阈 | 告警 + 抽样复核 |
| **质量层**| gold set R@P 衰减、申诉成功率突升 | 阈值重标 |
| **攻击层**| 红队新攻击成功率上升 | 输入规范化 + 规则硬拦 |
| **生态层**| 举报率/低质 VV 占比异动 | 回到 M1 查问题定义 |

可参考 [DriftGuard, arXiv:2606.28725](https://arxiv.org/abs/2606.28725) 的"多监控 + 选择性适配"框架。

## 九、策略迭代：什么时候该改策略（而不是改规则）

> 与 M1 §四平行。**判断标准是"问题归属"**：信号指向规则本身，就回 M1；指向实现手段，才是 M2 的事。

| 信号 | 真实含义 | 正确动作 | ❌ 错误动作 |
|---|---|---|---|
| 某风险类漏放集中，但规则表述清晰 | 模型特征不足 | **换骨干 / 加模态 / 补难例**| 改规则（会把对的改错） |
| 全类目误伤上升，规则未变 | 数据漂移或阈值失配 | **重标阈值 / 重校准**| 直接放阈值（会漏放底线） |
| 推理成本超预算，量级要涨 | 架构问题 | **加级联 / 换更小骨干 / FP8**| 降采样帧数到影响召回 |
| 新类目上线慢 | 编译链路问题 | **走语义热插拔 / 判例库**| 每次重训（周期太长） |
| 同一物料反复判错 | 缺指纹覆盖 | **物料指纹 + 纠错名单**（腾讯做法） | 反复训练 |
| 对抗样本绕过率上升 | 攻防节奏 | **输入规范化 + 红队**| 加算力硬扛 |
| 模型间置信度不可比 | 未校准 | **先校准再设统一阈值**（CAUC） | 直接拿原始分数比 |
| 离线涨了线上没动 | 指标鸿沟 | **影子模式 + 灰度定位**| 继续调离线 |
| 漏放与误伤同时恶化 | **规则不可判定**| **回 M1 改规则**| 在 M2 调参（白费） |

**最后一行是核心结论**：
> **漏放与误伤同时恶化，几乎一定是规则问题，不是模型问题。**
> 因为模型只会在两者之间做取舍，不可能同时变差——同时变差意味着"这个目标本身不可优化"，也就是 Policy 的定义没做完。

### 9.1 资产版本化（出事时能回滚）

**模型 / 提示词 / 阈值 / 策略 / 词库 / 判例库 六类资产必须版本化并记录生效时间**，因为生态指标异动时第一步就是"对齐时间线"。

## 十、常见反模式（自查表）

| 反模式 | 表现 | 根因 | 修法 |
|---|---|---|---|
| **全量大模型直推**| 成本随量级线性上涨 | 未做级联 | 前置轻量路由（>80% 拦截） |
| **离线 F1 达标就上线**| 线上指标不动 | 无影子模式/灰度 | 五步上线 |
| **显存充足还上 INT4 weight-only**| TPS 反而下降 | 反量化开销 | FP8 / AWQ |
| **缺失标签当负样本**| 路由 R@P 莫名偏低 | 未区分三态标签 | Validity-Aware Masking（+18.42 分） |
| **跨模型置信度直接比**| 阈值无法统一 | 未校准 | CAUC 式独立校准 |
| **阈值全局一个**| 各类目表现悬殊 | 未按风险类标定 | 分类目阈值（正例率 9.0%~25.5%） |
| **只看域内 gold set**| 新风险一来集体失效 | 对齐税 | experience replay + 持续回流 |
| **回扫缺位**| 新规上线后存量违规长期存在 | 无回扫机制 | 分级回扫 + 指标标注是否含回扫 |
| **只蒸馏不校准/不回流**| 学生模型衰减无感知 | 缺质量层监控 | 三层漂移监控 |
| **不防对抗**| 结构化模板/emoji 绕过 | 假设模型已对齐 | 输入规范化 + 格式异常升级人审 |
