## 00 · 两个方向都撞墙

多模态大模型（VLM/LLM）上线的第一天，内容安全团队通常会经历一次幻灭：模型能看懂极其隐晦的擦边球，却会在一条简单的"反诈科普视频"上把政务号封禁。

原因不在推理能力，在于把"需要多步取证的调查任务"，强行塞进了"单次前向传播（single-pass inference）"的静态窗口里。

但反过来，如果让 Agent 放开手脚自由调用工具，飙升的 Token 账单、不可控的长尾时延（P99）以及无法复现的判定路径，会立刻击穿审核底座的 SLA。

真正的工业级 AI Agent 审核，不是让大模型自己写提示词调工具（ReAct），而是把取证动作拆解为受限的有向无环图（DAG / 状态机），在算力预算的硬约束下，把"黑盒猜测"变成"结构化证据链拼图"。

## 01 · 单次推理救不了边界样本

### 一条 47 秒的视频

一条 47 秒的短视频，封面用繁体字写着"月入十万的秘密"，画面第 12 秒闪过一张银行卡特写，第 20 秒人物举牌写着 "DM me"，音轨是语速极快的西班牙语。

走传统的单次多模态判定：系统均匀抽取 8 帧图像，连同标题文本一起喂给模型。模型看到"高收益承诺 + 银行卡 + 私信导流"三个高危特征同时命中，给出**引流诈骗、置信度 0.93** 的封禁结论。在它被投喂的输入子集里，这个推理无懈可击。

但只要把视野拉出这 8 帧，事实完全反转：

- **时序盲区**：音轨在第 31 秒明确用西语说"以上都是骗子的标准话术，千万别信"。均匀抽帧漏掉了这个关键转折音轨。
- **模态精度盲区**：画面里的银行卡号只有 12 位（道具卡）；角落二维码解析出来的域名，属于官方反诈公益页。
- **外部上下文盲区**：该账号带有政务合作认证，过去 11 周连续发布同系列反诈剧集，且前两集均由人工复核放行。
- **政策例外盲区**：《导流治理规范》里有一条豁免：以揭露、警示为目的展示诈骗话术、且未提供真实可用联系方式的，不按引流处置。这条例外不在模型记忆里，在政策库里，带生效版本号。

单次模型判错，是因为判定所需的必要条件散落在精细时序切片、外部工具解析（二维码 / 卡号校验）、动态生效的政策例外条款，以及账号历史画像四个不同象限里。**问题出在输入集合，不在模型能力。**

判定任务本身也分两种形态。单次判定输入固定、输出一次；取证型判定是一串动作，每一步的输入取决于上一步的返回。后者更强，但不是万能药：真正需要它的只有一类内容——**拿不准，且判错不可逆**。

### 这笔账的两种算法

在生产环境里，通过多步工具调用把这四类证据全取回来，端到端通常要 5～8 秒。成本倍数取决于拿谁当基线，两个数字都真实存在，只是分母不同：

- 相对**单次 VLM 判定**：大约一个数量级（示意账里是 6 次工具 + 2 次模型调用、6.4 秒、约 9 倍）。
- 相对 **L1 快筛算子**：50～100 倍。

把全量内容都塞进这套流程，财务账单会当场爆炸。所以问题不是"该不该上 Agent"，而是"**哪 5% 的内容配得上这个价**"。

## 02 · 算力围栏：Agent 只接最贵的 5%

Agent 流程不是用来替代传统审核漏斗的，它是插在机审漏斗最末端、人审队列最前端的"高成本过滤器"。整条机审链路必须按算力单价与时延红线切分为三级，只有满足特定路由条件的内容，才允许触发 Agent 编排。

| 漏斗层级 | 核心组件与形态 | 耗时红线（P99） | 流量承接占比 | 职责与准入边界 |
|---|---|---|---|---|
| **L1 极速快筛** | 轻量判别式小模型 + 黑白名单特征匹配 | < 50 ms | 100% 全量 | 拦截显性违规（高置信度直接处置），放行绝对安全流量；**严禁在此层部署生成式模型** |
| **L2 动态采样** | 多模态分类模型 + 时序高危片段定位（滑窗 / 关键帧） | 500 ms – 1.5 s | 15% – 25% | 对存疑内容做帧级与音轨对齐定位；对"判错可逆"的轻度边界内容直接降权或限流分发 |
| **L3 Agent 编排** | 受限状态机 + 专职工具集 + 判据推理节点 | 5 s – 10 s | **严格卡死在 5% 以内** | 只承接"L2 置信度处于灰区 + 风险等级高（判错不可逆）"的复杂样本，定向取证定级 |

### 哪类标签才允许进 L3

不能靠算法工程师拍脑袋，必须在政策知识库（Policy Schema）建表时，由策略制定人为每条规则打上**证据拓扑标签**。这个字段决定了内容该不该上流程，是整笔账里最贵的决定。

- **全局表征型**（血腥暴力、显性色情）：靠 L1/L2 的视觉特征直接命中，**禁止进 L3**。上流程只是把钱烧在确定的事情上。
- **局部时序型**（直播口播导流、音频夹带辱骂）：需先由 L2 定位时间戳，再截取局部切片交给 L3 做高精度 ASR 与语义核验。
- **跨源证据组合型**（杀猪盘引流、资质造假、反讽科普）：单看画面或文本都正常，必须组合"政策例外条款 + 账号历史信誉 + 外部链接解析"才能定性。**这是 L3 唯一合法的主战场。**

### 四项熔断预算

黑产会利用复杂样本来打穿 L3 的算力池：批量提交"看起来值得深查"的内容，就能把工具并发配额耗尽。所以 L3 引擎必须在入口硬编码四道预算上限（budget caps）：

1. 单案最大 Token 消耗；
2. 最大状态转移步数（通常卡死在 5 步以内）；
3. 外部工具最大并发调用次数；
4. 端到端墙钟超时（wall-clock timeout）。

任一指标触顶，立即中止推理，携带已有证据链降级转入人审。**熔断不是失败，是一种有明确出口的降级。**

## 03 · 编排范式：放弃自由 ReAct，把控制流锁进状态机

工业界的 Agent 有两种控制流范式，差别不在用不用大模型，而在"下一步由谁决定"。

| 维度 | 模型驱动（Autonomous / ReAct） | 状态机驱动（Deterministic / DAG） |
|---|---|---|
| 控制流位置 | 在模型内部，模型自己决定下一步与停止时机 | 在工程代码里，状态转移硬编码 |
| 终止性 | 不可保证，可能不收敛 | 必然终止，路径可枚举 |
| 可重放 | 每次重跑路径可能漂移 | 每一跳都是有名字的状态，可精确复现 |
| 成本 | 逐例变动，单件成本无法预算 | 状态数固定，可提前算账 |
| 工具可见性 | 全量暴露，模型盲选 | 按状态最小权限暴露 |
| 适用场景 | 新风险探索、离线沙箱 | **内容安全的生产主干** |

内容安全的生产环境必须无条件选后者，理由有三条。

**合规重放与可审计性。** 处置结果在数周后可能遭遇申诉或监管问询，系统必须精确复现"当时基于哪一版政策、调了哪几个工具、排除了什么假设"。自由探索的 Agent 每次重跑路径都可能漂移，无法自证清白。

**消除长尾死循环。** 自由 Agent 面对模糊证据时，极易陷入"反复换关键词调检索工具"的死循环，导致 P99 延迟失控、单件成本无法核算。

**最小权限隔离。** 在 20 个工具里让模型盲选，幻觉率远高于在当前状态下只暴露 2 个指定工具。

### 标准架构：确定性取证主干 + 受限判据节点

以开篇那条"疑似引流视频"为例，状态机的工作流完全锁死：L2 触发后，三路取证并行发出——政策检索拉取带生效版本号的豁免条款，多模态取证针对时间窗并行触发多语种 ASR、卡号规则校验与二维码沙箱解析，上下文拉取读取账号认证标签与近 30 天同系列判罚记录；三路在判据节点汇聚，对照豁免条款的必填字段检查证据槽位是否齐备。

出口只有三个：槽位齐备且满足豁免，放行并自动挂载"反诈宣传"提示标签；槽位缺失（例如 ASR 置信度过低），触发定向补证、最多回跳 1 次；证据冲突或补证后仍存疑，打包结构化工单，路由至人工专审队列。

真正的自由探索 Agent 用在哪里？只用在离线的**新风险沙箱**里。新型黑产变体刚出现、策略团队还不知道该查哪些特征时，先让自由 Agent 在隔离环境里跑首批样本，把跑通的高频有效路径固化成确定性的状态机代码，再发布到线上主干。**探索和生产，是两条不能混用的流水线。**

## 04 · 工具层契约：消灭"模型脑补"与"空返回漏放"

Agent 的判断力上限，取决于底层工具返回数据的颗粒度。工具层设计粗糙，状态机编排得再精妙也是垃圾进、垃圾出。

| 工具 | 必须返回 | 严禁的做法 | 不遵守时的失效模式 |
|---|---|---|---|
| **政策检索** | 带 `Policy_Version_ID`、生效时间窗、正反例边界、强绑定豁免条件、类型化字段的 JSON Schema | 只做向量相似度匹配 | 拿到已废止条款或漏掉例外，判得"有依据地错"，申诉时最难解释 |
| **判例库** | 相似案例作为对比参考字段；物料加密指纹（MD5 / 感知哈希）匹配结果 | 直接复用历史结论 | 科普视频第 45 秒插 1 秒闪帧，画面 99% 相同、性质完全不同 |
| **多模态算子**（ASR / OCR / URL 沙箱） | 原文切片 + 置信度 + 时间戳，例如 `{"type":"bank_card","ocr_text":"622202…","digit_length":12,"confidence":0.89,"timestamp":"00:12.4"}` | 只返回布尔值；把超时当阴性 | "没查出来"被下游读成"没有违规"，一次漏放变成报表上的一次正常判定 |
| **上下文画像** | 特征更新时间戳 + 实时滑动窗口计数（如近 5 分钟发帖频次） | 只给离线 T+1 画像 | 刚发作的被盗号、批量黑产号在画像里仍显示"信用良好" |

**政策库要结构化，不能只做 RAG 切块。** 直接用向量检索政策文档，极易拿回"已废止的历史条款"或"漏掉下半段的例外说明"，导致模型做出看似有理有据、实则完全错误的判罚。政策知识库必须是带版本号与生效窗口的结构化对象，豁免条款以强绑定字段的形式挂在主条文下面。

**判例只能参考，不能短路。** "像"和"是"的差别，正是判定要处理的东西。只有当物料指纹 100% 匹配、且属于已登记的白名单物料时，才允许直接复用结论。

**取证算子严禁返回布尔值。** 工具不能只返回 `has_bank_card: true`，必须返回原文切片、置信度和时间戳。判据节点看到的是"第 31 秒，置信度 0.71，原文如下"，而不是一个 true。同时必须严格区分两类空结果：**阴性结果**（查了，确实没有）与**调用失败**（超时、报错）。算子超时返回空值时，状态机必须捕获异常并打上 `Evidence_Missing` 标记，绝不能让下游把"没查出来"当成"没有违规"。

**上下文必须显式标注延迟。** 刚开始发作的被盗号或批量黑产号，离线 T+1 画像往往还显示"信用良好"。上下文接口返回时必须附带特征更新时间戳，并与实时滑动窗口计数器一起喂给判据节点。

## 05 · 人机交接与灰区准入：什么时候停手，怎么防锚定

Agent 不是万能的。强行让 Agent 消化所有疑难杂症，只会把"不确定"变成"高置信度的误判"。系统必须硬编码五条强制转人审出口。

| # | 触发条件 | 系统强制动作 | 移交人审工单的核心载荷 |
|---|---|---|---|
| 1 | 定向补证达上限（首轮 + 回跳 1 次，共 2 轮） | 停止循环，冻结状态 | 已验证成立的证据项、当前唯一缺失的判据槽位 |
| 2 | 核心取证工具超时或报错 | **严禁默认放行**，转异常队列 | 失败的算子名、错误码、待核验的原始音视频时间戳 |
| 3 | 跨模态证据强冲突 | 拒绝自动定级，转专家队列 | 冲突双方证据明细（如画面命中高危导流，但账号属政务白名单） |
| 4 | 高危红线类目（P0/P1）但置信度居中 | 临时熔断分发（Hold），高优转人工 | 命中的高危政策条目 ID、疑似违规切片定位 |
| 5 | 算力或墙钟预算触顶 | 降级为存疑工单 | 触发熔断的预算维度（Token / 步数 / 耗时）、半成品证据链 |

### 两个关键工程细节

**结构化交接，拒绝"只传结论"。** 如果只把视频和一个"机器存疑"标签扔给审核员，人审只能从头看一遍 47 秒视频，Agent 前面花的算力全部打水漂。工单必须高亮展示已提取的时间戳切片（直接定位到第 31 秒音频）与待确认的单一问题，把人审从"大海捞针"变成"按图索骥的填空题"。

**防锚定盲测。** 在处理高争议边界样本或申诉复核时，如果第一屏就展示大模型写得头头是道的推理链（CoT），审核员会形成严重的心理锚定，退化成无脑点同意的橡皮图章。工作台必须**先盲判、后展开**；高价值样本可启用"2 异构模型 + 1 人工"的互不可见多数决投票，且严禁把不同底座模型的输出概率（logits）直接加权平均——它们不可比，只能计票。

### 中间那一档：受限分发

在"直接封杀"与"完全放行"之间，针对 P2/P3 级低危边界内容（轻度低质诱导、疑似营销），Agent 可以直接输出第三档处置：**受限分发**——不进公域推荐池，仅粉丝可见，并绑定强制 TTL。24 小时内自然互动未触发二次告警则自动归档；热度异动立即提权回流人审。这一档的作用，是避免灰区内容变成无人清理的死水。

## 06 · 审计重放与三类生产级故障

判断一套 Agent 审核系统能不能上生产，不看它在 Demo 集上的准确率，而看它能不能在周度迭代中不翻车、出了错能不能在 5 分钟内定位到具体哪一跳。

每一次执行完毕，必须落库全链路追踪日志（trace log），锁死 7 个核心归因字段：

`Trace_ID` · 状态转移路径序列 · 各算子调用入参/出参摘要与耗时 · 命中的 `Policy_Version_ID` · Prompt 与模型底座版本 · 引用的证据字段指针（evidence pointer）· 最终定级与降级原因码。

这套字段服务三件事：申诉时重放、改版时回归、出问题定位到某一跳。结论错了，错在政策检索拿到旧版本、转写丢了关键句、还是判据节点判反，修法完全不同——而只看结论的日志里，它们长得一样。

基于这套日志底座，工程团队必须重点防御三类生产级故障。

**故障一：模型证据幻觉。** 现象是模型输出的定级理由格式完美、逻辑严密，写着"画面右下角存在微信收款码"，但复盘 OCR 与视觉算子的原始返回，里面根本没有这一项——模型顺着高频判例自己"脑补"了证据。防御是**引注指针强校验**：判据节点输出 JSON 时，每条定罪论据必须附带上游工具返回的原始字段 ID（如 `"evidence_ref": "tool_ocr_output.box_3"`），后置校验一旦发现指针为空或与原始输出不匹配，直接拦截该结论并打回重判或转人审。

**故障二：策略与工具级联漂移。** 现象是语音转写团队升级了 ASR 模型，或政策团队改了某条豁免规则的表述，没有通知 Agent 团队，次日某条分支路径的转化率暴跌或误伤翻倍。防御是**路径级回归集 + 影子模式**：把历史上判错并修正过的典型 case 按状态机路径归档；任何工具版本升级或 Prompt 改动，除对比最终准确率外，必须在影子模式下监控状态转移分布偏移率与工具异常率。

**故障三：算力雪崩与降级风暴。** 现象是黑产集中批量发布带有复杂多语种混排、模糊二维码的"擦边但不完全违规"视频，故意穿透 L1/L2 漏斗，瞬间打满 L3 的工具并发配额，大量工单因超时熔断涌入人审队列，把人审池冲垮。防御是**读写分离 + 动态漏斗削峰**：一方面，Agent 只能输出"处置建议工单"，真正的封号、删帖执行器必须剥离在 Agent 进程之外，由带速率限制的下游网关统一执行；另一方面，实时监控 L2→L3 升级转化率，一旦某类特征触发异常洪峰，自动将该分支降级为"临时限流（hold）+ 异步延时队列排队"，优先保住核心链路水位。

## 07 · 结语：把好钢用在刀刃上

再看一眼开头那条 47 秒的反诈视频。通过 3 步并行取证，我们花了比普通快筛贵几十倍的算力和额外的 6 秒钟，保住了一个优质创作者的合规内容。

这笔账算得过来，只有一个前提：**95% 的简单内容已经在前两级漏斗被低成本消化，而剩下的 5% 走了一条严格受控、步步留痕、随时可熔断的状态机流水线。**

把不确定的取证变成确定的工程编排，才是 AI Agent 在内容安全落地的真正壁垒。模型会换、工具会升级、政策会改版，但"哪一步取什么证、证据放在哪个槽位、什么时候必须交给人"这套骨架，是能跨模型版本活下来的资产。

## 口径与边界

1. **数字性质**：文中 47 秒案例、6.4 秒、9 倍成本、5～8 秒、50～100 倍、单案 5% 占比均为量级示意（来自公开部署数字与预算反推），不代表任一平台的实测值。成本倍数有两档基线——相对单次 VLM 判定约一个数量级，相对 L1 快筛算子 50～100 倍——引用时请连基线一起写。
2. **阈值口径**：50 ms、500 ms–1.5 s、5 s–10 s 是 P99 红线；若写进 SLA 承诺，必须同时声明统计口径（P50 还是 P99）与采样窗口。
3. **时限与配额**：`max_retries = 1`、5 步以内、24 小时 TTL 是常见取值，不是定论；不同风险类目的合理值差别很大。
4. **一手材料缺口**：L2 采样质量的公开指标（STEC, WACV 2026 Workshop）、视频级多帧判定的单卡耗时（arXiv:2504.14904）、编排按状态转移计价的成本模型（AWS Trust & Safety 参考实现）见文末参考。
5. **不主张什么**：本文不主张"Agent 应该接管大部分审核流量"，也不主张"ReAct 无用"——它只是不该出现在生产主干上。
