## 01 · 问题形式化：单次判定的输入完备性缺陷

内容审核的完整判定逻辑可以形式化为一个依赖三类外部状态的函数：

$$y = f(x^*, p_v, c_t)$$

其中，$x^*$ 表示待审内容的完整多模态表征，$p_v$ 表示带生效版本号的现行政策及附属豁免条款，$c_t$ 表示当前时刻的账号与历史处置上下文。

传统的单次多模态判定（Single-Pass VLM）实际求解的是一个输入严重受限的近似函数 $\hat{y} = f_{\text{VLM}}(\tilde{x})$，其中 $\tilde{x}$ 通常是均匀抽帧与标题文本的固定窗口拼接。无论底座模型参数量如何扩展，单次判定都受限于四类结构性输入缺失：

| 缺失维度 | 工程成因 | 典型失效表现 |
| :--- | :--- | :--- |
| **时序表征缺失** | 均匀抽帧或截断采样跳过关键时间切片 | 遗漏反转语境、短时闪现画面或后半段口播声明 |
| **细粒度与外部对象缺失** | 低分辨率图像输入与封闭推理环境 | 无法校验卡号/联系方式有效性，无法解析二维码或短链指向 |
| **实时上下文缺失** | 无状态单次调用不具备实时状态查询能力 | 缺失账号认证属性、近期违规频次与系列内容历史复核结论 |
| **动态政策版本缺失** | 规则与豁免条件高频迭代，无法及时内化进模型权重 | 忽略带版本号的豁免条款，或依据已废止口径做出「有依据的误判」 |

引入 Agentic 编排的工程本质，不是提升模型单步推理能力，而是通过有状态的外部工具调用，将输入集合从 $\tilde{x}$ 补全至 $(x^*, p_v, c_t)$。

但补全输入集合的代价极高：一次典型的多工具取证流程包含 2 次左右模型调用与多次异构算子调用，端到端耗时约 5–10 秒，单案算力成本**相对单次 VLM 判定约 9×，相对 L1 判别式快筛约 50–100×**（示意量级）。因此，构造 Agentic 审核系统的核心工程约束在于：如何在严格的成本与尾延迟预算内，实现**确定性路由、可重放编排、强契约取证与可控降级**。

## 02 · 流量路由与三级漏斗构造

### 预算倒推的流量上限

在工业级内容平台中，L3（Agentic 取证层）的流量占比不是按准确率拍脑袋设定的目标，而是由算力预算与吞吐硬约束倒推出来的上限：

$$\text{Ratio}_{L3} \le \frac{B_{\text{daily}}}{C_{L3} \times Q_{\text{daily}}}$$

其中 $B_{\text{daily}}$ 为可承受的日算力预算，$C_{L3}$ 为单案均摊成本，$Q_{\text{daily}}$ 为日审总量。参考公开部署数据，视频级多帧 VLM 单卡耗时已达约 7 秒（[KuaiMod, arXiv:2504.14904](https://arxiv.org/abs/2504.14904)），而图片级 VQA 约 0.2 秒，两者吞吐相差约 35 倍；叠加多路外部工具调用后，线上通常只能将 L3 流量上限锁死在 **≤ 5%**。

### 三级漏斗与 L2 / L3 算子分层

整条机审链路由前向后按 P99 时延红线与算力单价切分为三级，L3 位于机审最末端、人审最前端：

| 漏斗层级 | 核心组件 | 时延红线（P99） | 流量占比 | 相对 L1 成本 | 职责与输出边界 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **L1 极速快筛** | 判别式小模型 + 黑白名单 + 规则引擎 | < 50 ms | 100% | 1× | 拦截显性违规、放行绝对安全流量；严禁接入生成式模型 |
| **L2 动态采样** | 多模态分类 + 轻量 OCR/ASR + 时序定位 | 500 ms – 1.5 s | 15% – 25% | ≈ 10× | 粗粒度图文音提取与对齐；P2/P3 可恢复边界直接走受限分发 |
| **L3 Agent 编排** | 受限状态机 + 按需深查工具 + 判据节点 | 5 s – 10 s | ≤ 5% | 50–100×（相对 VLM ≈ 9×） | 仅接高危不可逆灰区与重罚豁免核验样本 |

L1 的 50 ms 必须按 **P99** 而非 P50 承诺——高并发审核场景下，P50 达标但 P99 抖动依然会引发上游排队雪崩。

在算子职责切分上，L2 与 L3 必须避免重复计算：

- **L2 承担全量粗提取**：完成关键帧抽取、通用语种快速 ASR 与基础画面文字识别，输出结构化特征供分类器打分，并作为初始上下文透传给下游。
- **L3 承担按需深查**：仅针对 L2 标记出的疑点区间或特定门控条件，触发小语种高精重转写、局部 ROI 放大识别、二维码/短链沙箱解析、联系方式格式校验、实时账号画像与政策豁免字段拉取。

### 确定性准入闸门与 `detection_shape`

能否进入 L3 不能仅凭单模型置信度决定——单模型在缺失豁免条款或关键帧时，同样会给出高置信度误判。L3 的准入条件应形式化为一条确定性的布尔谓词：

$$\text{Enter}_{L3} = (\text{GrayZone} \cap \text{IrreversibleRisk}) \cup (\text{HardPenalty} \cap \text{HasExemption} \cap \text{shape} \in \{\text{segment}, \text{crossmodal}\})$$

- **前半支（防不可逆漏放）**：置信度处于灰区，且一旦漏放无法通过事后手段挽回（如 P0/P1 高危风险）。
- **后半支（防不可逆误杀）**：拟执行封号、下架等不可逆重罚，且命中的政策条目存在豁免条款、风险形态依赖跨片段或跨模态关联。

为此，政策知识库（SSOT）建表时需为每条规则绑定一个与风险类目正交的 `detection_shape` 字段：

| `detection_shape` | 风险藏匿结构 | 链路采样要求 | 是否允许进 L3 |
| :--- | :--- | :--- | :--- |
| `global` | 单帧或单句即可定性（显性色情、血腥） | L1/L2 判别式分类足够 | 禁止 |
| `keyframe` | 整条视频仅极少数帧含违规元素 | L2 高熵帧定位 + 局部裁剪 | 仅高危存疑准入 |
| `segment` | 连续时间片段的音画共同构成语义 | 时序滑窗 + 完整语境 ASR | 允许 |
| `crossmodal` | 单模态均合规，多模态叠加才触发违规或豁免 | 跨模态关联 + 外部工具查证 | 核心准入 |

在工程协作上，政策团队负责定义结构化的风险要素与豁免条件清单，策略产品与算法团队将其映射为 `detection_shape`，在 SSOT 规则发布前联合评审签字。

## 03 · 编排内核：受限状态机、熔断预算与读写分离

### 控制流归属：受限状态机 vs. 自由 ReAct

生产审核主干面临的核心架构选型是控制流放在模型内（自由 ReAct）还是放在编排层（受限状态机）：

| 维度 | 控制流在模型内（自由 ReAct） | 控制流在编排层（受限状态机） |
| :--- | :--- | :--- |
| 路径决策 | 运行时由模型自主规划 | 代码定义的确定性条件路由 |
| 终止保证 | 依赖模型自我收敛，存在发散风险 | DAG/有界回跳拓扑硬约束，必然终止 |
| 审计与重放 | 动态路径难以复现 | 每个状态具名落库，支持申诉期精确重放 |
| 成本核算 | 单案波动大，无法提前做容量规划 | 路径集合有限且有界，可精确核算单价 |
| 工具权限 | 全量工具暴露，误调与越权风险高 | 按状态节点最小权限暴露（每节点 2–3 个工具） |

线上审核主干必须采用**受限状态机**。这一选型直接对应三个生产硬约束：申诉与合规审计要求事后精确重放、高并发要求成本与时延严格有界、数据安全要求工具按状态最小权限隔离。正如 [Anthropic《Building effective agents》](https://www.anthropic.com/research/building-effective-agents) 对预定义工作流（Workflows）与自主智能体（Agents）的边界划分：任务路径可预判且强调确定性与可审计性时，应使用预定义工作流；开放式自主规划仅适用于路径未知的探索场景。

### 执行拓扑：特征门控主干 + 单一判据节点

绝大多数取证触发条件是确定性的（命中外语高语速音轨触发高精 ASR、命中疑似外链/二维码特征触发沙箱解析、命中带豁免条款的标签触发政策槽位检索），直接写在编排代码的特征门控中即可。整个 L3 中真正需要大模型介入的只有**判据节点（LLM Evaluator）**：依据上游已取回的证据切片与政策必填槽位，输出结构化评估结果。

### 四项硬编码熔断预算

对抗环境下，入口必须外挂四道硬编码熔断器，任一触顶立即中止状态机，携带已有证据链降级转人审：

1. **单案最大 Token 消耗**：截断超长转写输入或异常推理膨胀。
2. **最大状态转移步数（硬上限 5 步）**：此处「1 步」定义为状态机的一次节点流转。通用 Agent 工程实践中常将 p99 放宽至 15 步，但审核主干对尾延迟极度敏感，必须将硬上限锁死在 5 步以内（覆盖首轮并行取证 + 最多 1 次定向补证）。
3. **外部工具最大并发与累计调用次数**：防止单卡 Token 漏掉「低 Token、高频轮询下游 API」的循环消耗。
4. **端到端墙钟超时（Wall-Clock Timeout）**：隔离外部沙箱或下游微服务慢响应，防止工作池耗尽。

### 读写分离与离线探索沙箱

- **读写分离**：删帖、封号、限流、打标等写操作物理隔离在 Agent 进程边界之外。状态机只输出只读的 `ActionRecommendation` 与证据链，由外置的、带速率限制与幂等校验的**处置执行网关**统一落库，从架构上消除模型越权误操作风险。
- **离线探索沙箱**：对于无现成取证清单的新型黑产或新上线政策，在隔离的离线沙箱中运行自由探索 Agent，提取其高频有效路径并经人工评审后，固化为新的状态机代码分支再发布上线。

## 04 · 接口层构造：四类工具的返回契约与证据引用 Schema

状态机的判定上限取决于工具层接口契约的严谨度。四类核心工具必须严格区分语义状态并禁止隐式兜底：

| 工具类别 | 契约必返字段 | 禁止的反模式 | 典型失效模式 |
| :--- | :--- | :--- | :--- |
| **政策检索** | `policy_version_id`、生效时间窗、强绑定豁免条款与必填槽位 | 纯向量相似度检索 | 召回已废止条款，产生「有依据的误判」 |
| **判例库** | 相似案例摘要（只读参考）、物料指纹精确匹配标识 | 直接复用相似案例结论 | 画面高度相似但语境/口播反转，导致批量误杀 |
| **多模态深查算子** | 三态 `status`、原始文本/对象切片、时间戳、置信度、`evidence_id` | 仅返回布尔值；将超时默认置为 `false` | 下游把「调用失败没查出」误读为「无违规」 |
| **实时上下文画像** | 实时滑动窗口计数 + 离线特征更新时间戳（`updated_at`） | 仅返回 T+1 离线信用分 | 盗号突发攻击期仍被识别为「历史信用良好」 |

多模态深查算子必须强制实现**三态返回语义**：`ok`（命中具体对象并附带 `evidence_id`）、`negative`（执行成功且确认无目标对象）、`timeout` / `error`（执行异常）。只要核心算子返回异常，状态机必须写入 `EVIDENCE_MISSING` 标记，阻断自动放行路径。

## 05 · 终局收敛：强制转人审出口、防锚定工作台与受限分发闭环

### 五条硬编码强制转人审出口

状态机不得强行对不确定样本输出自动终局，以下五种条件触发时必须无条件转交人工队列：

| # | 触发条件 | 强制动作 | 工单必带载荷 |
| :--- | :--- | :--- | :--- |
| 1 | 补证达上限（首轮 + 定向回跳 1 次，共 2 轮） | 冻结状态，终止循环 | 已验证槽位列表、唯一缺失槽位 |
| 2 | 核心深查算子异常（`EVIDENCE_MISSING`） | 严禁默认放行，转异常队列 | 失败算子名、错误码、耗时 |
| 3 | 跨模态证据强冲突（违规特征与豁免证据置信度接近） | 拒绝自动定级，转专家队列 | 冲突双方的 `evidence_id` 与原始切片 |
| 4 | 命中 P0/P1 高危条款但判据置信度居中 | 临时阻断公域分发，高优转人审 | 高危 `policy_version_id`、切片时间戳 |
| 5 | 四项熔断预算任一触顶 | 立即降级为存疑工单 | 触顶维度、已采集的半成品证据链 |

### 结构化工单与防锚定工作台

转人工的工单必须携带时间戳定位切片与单一待决问题，避免审核员从头重看全量素材导致前置算力失效。

针对高争议样本与申诉复核，工作台界面第一屏**禁止默认展示模型的推理链与建议结论**，强制执行「先盲判、后展开证据」以消除锚定效应。极高价值样本可配置「两路异构模型 + 一位人工」的互不可见多数决，模型分歧时由人工一票决胜；由于不同底座模型的置信度未经统一校准，聚合层只计票不做概率加权（完整机制见系列文章 *EdgeCase Framework*）。

### 受限分发（24h TTL）的路由归属与到期闭环

在直接放行与直接封禁之间，系统引入「受限分发」（不进公域推荐池、仅粉丝/主页可见、绑定 24 小时 TTL）作为可回收的中间保护态。其路由与到期规则必须严格写死，避免与 L3 准入边界冲突或演变为无人清理的永久限流池：

- **路由归属**：P2/P3 级判错可恢复的边界内容主要由 **L2 直接分流**至受限分发，不消耗 L3 算力；L3 仅在 P1 高危待复核或降级削峰阶段借用该状态做临时阻断。P0 违法内容严禁走受限分发，必须严格拦截（与 [KuaiMod (arXiv:2504.14904)](https://arxiv.org/abs/2504.14904) 的风险分层边界一致）。
- **到期闭环**：TTL 窗口内若播放量、互动率或举报斜率触及告警阈值，立即提权回流人审；24 小时到期且未触发异动时，**P2 级强制回流人审队列完成终局闭环**，**P3 低危级自动归档并按固定比例进入事后抽检池**。

| 风险等级 | 放行 | 提示标签 | 受限分发（24h TTL） | 人工审核 | 直接封禁 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **P0 违法（不可逆）** | 不适用 | 不适用 | 严禁 | 存疑高优复核 | 默认 |
| **P1 高危（不可逆）** | 不适用 | 不适用 | 仅作人审前临时阻断 | 默认终局 | 高置信自动 |
| **P2 违规（可恢复）** | 不适用 | 不适用 | L2 默认（到期回人审） | 异动/到期复核 | 确认后执行 |
| **P3 边界（低危）** | 条件放行 | 默认 | L2 可选（到期归档+抽检） | 抽检/申诉复核 | 不适用 |

## 06 · 生产可观测性、后置校验与三类静默故障防御

生产系统的可维护性取决于单案可追溯粒度。每次 L3 执行完毕，必须落库包含 7 个锁定字段的追踪日志：`trace_id`、`state_path`（状态转移序列）、`tool_io_latency`（各算子入参/出参摘要与耗时）、`policy_version_id`、`model_prompt_version`、`evidence_refs`、`verdict_and_degrade_code`。

线上最危险的三类故障，既不会暴露在静态离线 Demo 集中，也会被占 95% 的简单流量稀释，在大盘总体准确率指标中几乎不可见：

| 故障类型 | 失效机制 | 工程防御手段 | 核心告警指标 |
| :--- | :--- | :--- | :--- |
| **模型证据幻觉** | 判据节点按高频先验编造上游算子并未返回的证据（如虚构收款码或违规句） | **引注指针强校验**：状态机离开判据节点时运行确定性代码校验，指针缺失或悬空即拦截转人审 | 指针校验失败率 |
| **策略与工具级联漂移** | 上游静默升级 ASR/OCR 模型或微调政策措辞，导致特定细分分支误伤翻倍 | **路径级回归集 + 影子模式**：按 `state_path` 归档历史纠偏案例，变更前对比分支转移分布偏移 | 状态转移分布偏移率、算子异常率 |
| **算力雪崩（容量型 DoS）** | 黑产批量构造多语种/模糊外链等诱导深查样本，打满 L3 并发并将超时工单灌爆人审池（见 [From Shield to Target, arXiv:2606.14517](https://arxiv.org/abs/2606.14517)） | **读写分离 + 动态削峰**：外置限流执行网关；`L2→L3` 转化率斜率突升时对该分支自动降级限流并切异步持久化队列 | `L2→L3` 转化率斜率、人审积压斜率 |

### 引注指针后置校验实现

防御证据幻觉不能依赖 Prompt 约束，必须在编排层执行确定性的指针集合校验：

```python
def verify_evidence_refs(tool_outputs: list[dict], evaluator_output: dict) -> tuple[bool, str]:
    """校验判据节点引用的每条 evidence_ref 均真实存在于状态为 ok 的上游工具返回中。"""
    valid_ids = {
        item["evidence_id"]
        for out in tool_outputs
        if out.get("status") == "ok"
        for item in out.get("items", [])
    }

    slot_checks = evaluator_output.get("slot_checks", [])
    if not slot_checks:
        return False, "EMPTY_SLOT_CHECKS"

    for check in slot_checks:
        ref = check.get("evidence_ref")
        if not ref or ref not in valid_ids:
            return False, f"DANGLING_EVIDENCE_REF:{ref}"

    return True, "OK"
```

校验返回 `False` 时，编排层丢弃模型建议，将 `DANGLING_EVIDENCE_REF` 写入 `verdict_and_degrade_code`，直接路由至人工审核队列。

## 07 · 架构演进与尚未闭环的工程债

上述构造解决了线上可控性、可重放性与单案成本封顶问题，但在完整治理闭环上仍有三项明确的工程债待解决：

1. **P0 漏放召回率的独立度量路径**：P0 严重违规漏放后通常不会进入用户申诉池，不能以申诉数据反推召回率，必须建设独立于申诉池的外部监管锚点与持续主动抽样审计链路。
2. **非故障路径的回归样本覆盖**：当前路径级回归集主要沉淀自「线上误判并被修正」的历史工单，正常放行与未爆发故障的分支缺乏代表性样本，上游工具换代时仍存在静默退化盲区。
3. **L3 到 L1/规则引擎的例行沉淀机制**：当 L3 在某类高频模式（如特定白名单特征或固定变体组合）上形成稳定判定后，需要建立定期将其蒸馏回小模型或卸载至 L1 规则引擎的自动化闭环，以持续压低 L3 流量水位。

在模型底座、工具算子与政策条款持续更迭的背景下，真正具备长期复利价值的不是某版 Prompt，而是这套显式接口契约与状态骨架——准入谓词、分层算子、有界状态机、强引用校验与分级兜底闭环。

## 口径与边界

1. **量级示意**：文中 5–10 秒端到端耗时、9×（相对单次 VLM）、50–100×（相对 L1 快筛）及 ≤ 5% L3 占比均为结合公开部署数据与预算约束反推的量级示意，不代表任一平台实测值；引用成本倍数时需连同基线一起声明。
2. **时延统计口径**：50 ms、500 ms–1.5 s、5 s–10 s 均为 P99 红线；写入正式 SLA 时须同步声明采样窗口与流量分母。
3. **阈值取值范围**：硬熔断 5 步、定向回跳 1 次、24 小时 TTL 属于短视频内容治理场景的常见工程取值，不同风险类目与业务形态需按实测分布调整。
4. **不主张什么**：本文不主张用 Agent 接管大部分审核流量，也不否定自由 ReAct 在离线风险探索中的价值，仅反对将无界自主规划直接置于高并发生产审核主干上。
