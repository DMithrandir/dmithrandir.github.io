一条 47 秒的短视频，封面用繁体字写着「月入十万的秘密」。第 12 秒闪过一张银行卡特写，第 20 秒人物举牌写着 "DM me"，音轨是语速极快的西班牙语。

系统均匀抽了 8 帧，连同标题喂给多模态模型。高收益承诺、银行卡、私信导流，三条线索叠在一起。模型判「引流诈骗」，置信度 0.93。在它看到的输入里，这个推理没有错。

错的是输入。第 31 秒的西语口播说的是「以上都是骗子的标准话术，千万别信」，均匀抽帧跳过了这句。银行卡号只有 12 位，是道具。角落二维码扫出来是官方反诈公益页。账号有政务合作认证，连续 11 周更新同系列反诈剧集，前两集都经人工复核放行。政策库里还有一条豁免：以揭露、警示为目的展示诈骗话术，且未提供真实可用联系方式的，不按引流处置。这条例外带着生效版本号，不在模型权重里。

换一条流程，三步取回来。查政策，拿到豁免条款和它的必填字段。取证，语音转写、卡号校验、二维码解析并行发出。查上下文，账号认证、历史判罚、前两集结论。豁免的两个条件各自有了对应的返回字段，结论从「封禁」改成「通过，加一条反诈提示标签」。

代价：6 次工具调用、2 次模型调用，端到端 6.4 秒，成本约等于单次判定的 9 倍。这些数字是示意的，只用来看量级。单模型那一次是 0.9 秒、1 个成本单位。为把一条视频判对，多花六秒和八倍的钱。

**问题出在输入集合，不在模型能力。**

绝大多数内容单次判定就能判对。把它们也塞进流程，账单按九倍算，准确率不动。这篇要回答的是：哪一段流量值得走流程，流程长什么样，走完怎么知道它判对了。

## 01 · 哪些内容需要走流程

单次判定输入固定、输出一次，像一个函数。取证型判定是一串动作，每一步的输入取决于上一步的返回。后者更强，但不是万能药。

| 内容 | 单次判定的表现 | 该走的路 |
|---|---|---|
| 明确违规、明确正常 | 判得准，置信度高 | 不进流程，直接出结论 |
| 边界内容，判错可恢复 | 判不准，最坏结果是移出推荐 | 限流发布，事后复核 |
| 边界内容，判错不可逆 | 判不准，漏放后收不回来 | 走流程，取证到能定级 |

第三行是流程存在的理由。它的数量决定流程的规模，也决定这笔钱该花多少。

成本倍数取决于拿谁当基线。相对单次 VLM 判定，大约一个数量级（示意账里是 9 倍）。相对 L1 快筛算子，50～100 倍。端到端通常 5～8 秒。两个数字都真实存在，只是分母不同，引用时请连基线一起写。

把全量内容都塞进这套流程，财务账单会当场爆炸。所以问题不是该不该上 Agent，是哪 5% 的内容配得上这个价。

## 02 · 漏斗把 Agent 卡在最后一小段

Agent 流程插在机审漏斗最末端、人审队列最前端。整条链路按算力单价与时延红线切分为三级，只有满足路由条件的内容才触发 Agent 编排。

| 漏斗层级 | 核心组件 | 耗时红线（P99） | 流量占比 | 准入边界 |
|---|---|---|---|---|
| L1 极速快筛 | 判别式小模型 + 黑白名单 | < 50 ms | 100% | 拦显性违规，放绝对安全流量；不能用生成式模型 |
| L2 动态采样 | 多模态分类 + 时序定位 | 500 ms – 1.5 s | 15% – 25% | 帧级与音轨对齐定位；判错可逆的直接降权 |
| L3 Agent 编排 | 受限状态机 + 判据节点 | 5 s – 10 s | ≤ 5% | 只接灰区 ∩ 判错不可逆 |

50 毫秒是架构红线，不是优化目标。写进承诺之后，L1 就锁定为判别式模型加量化推理，不能用生成式。口径也要一起定：这 50 毫秒是 P50 还是 P99。审核流量是海量的，P50 达标而 P99 失控，队列照样堆。

这个数字锁死了 L1 的技术选型。

5% 也不是保守估计。视频级多帧 VLM 判定摊到单卡约 7 秒（[KuaiMod, arXiv:2504.14904](https://arxiv.org/abs/2504.14904)），图片级 VQA 约 0.2 秒，两者差约 35 倍。完整的多工具 Agent 比单次 VLM 还贵一个量级，能接的比例只会更低。

### 哪类标签才允许进 L3

不能靠算法工程师拍脑袋。政策知识库建表时，每条规则要带一个 `detection_shape` 字段，写清风险藏在哪种结构里：

| detection_shape | 长什么样 | 对链路的要求 |
|---|---|---|
| `global` | 一帧、一句就能判（显性色情、血腥） | 分类模型够，禁止进 L3 |
| `keyframe` | 整条视频只有一两帧有问题 | 帧级定位，均匀采样必漏 |
| `segment` | 某几秒连续才构成完整语义 | 时序滑窗 + ASR |
| `crossmodal` | 单模态都正常，叠起来才违规 | 必须上 Agent 做关联推理 |

这个字段该由写政策的人填，不该由工程侧猜。它和标签体系是正交的：标签回答「这是什么风险」，`detection_shape` 回答「风险藏在哪种结构里」。只有标签没有形态，采样策略会漏；只有形态没有标签，判定没有依据。

填这个字段是整笔账里最贵的决定。不做的话，链路只能按最贵的方式兜底，所有边界样本都上流程，成本会把方案否掉。一家平台的安全团队在公开分享里给过一个组合型的例子：昏暗夜店画面配「招聘」「工资」封面，单看画面是场景，单看文字是招工，合起来才指向另一类内容（[AICon 深圳 2025](https://www.infoq.cn/article/6r251b2u2bdaqmgbisfa)）。

### 四项熔断预算

黑产会批量提交「看起来值得深查」的内容，把 L3 的工具并发配额耗尽。所以入口必须硬编码四道上限：单案最大 Token 消耗、最大状态转移步数（通常 5 步以内）、外部工具最大并发调用次数、端到端墙钟超时。

任一触顶，立即中止推理，携带已有证据链降级转入人审。只卡 token 抓不住「便宜但高频」的循环，比如把下游 API 打 200 次。四道必须同时卡。

## 03 · 谁决定下一步

编排有两种形态。一种把控制流放在模型里，模型自己决定下一步查什么、查到什么时候算完。另一种把控制流放在流程里，状态机决定下一步，模型只在指定节点上判断。

| 比较项 | 控制流在模型里（ReAct） | 控制流在流程里（状态机） |
|---|---|---|
| 谁决定下一步 | 模型 | 编排层 |
| 什么时候停 | 模型判断，可能不收敛 | 流程定义，必然终止 |
| 事后能否重放 | 难，路径是运行时生成的 | 能，每步是有名字的状态 |
| 成本 | 逐例变动，无法预算 | 路径固定，可提前算账 |
| 工具可见性 | 全量暴露，模型盲选 | 按状态最小权限暴露 |

审核必须选后者。最硬的理由是重放：一次处置可能在几周后被申诉，那时要回答「当时看到了什么、依据哪条政策、为什么排除另一种解释」。把任务整段交给模型跑一遍，复现同一结果基本做不到（[Scott Logic, 2026-07](https://blog.scottlogic.com/2026/07/08/auditable-agentic-orchestration.html)）。

还有一条更深的理由。Anthropic 在《Building effective agents》里给了自主 Agent 成立的强条件：任务要能快速验证对错，Agent 才能拿验证结果迭代下一步。审核没有这个条件。反馈是延迟的（申诉要等用户反应过来）、稀疏的（只有部分人会申诉）、有偏的（申诉成功池不代表全量）。ReAct 在治理场景缺少它赖以成立的那块地基。

### 取证清单是可枚举的

「控制流必须在流程里」听起来像断言。它能成立，是因为取证动作本身大多不需要模型裁决：

| 条件 | 必然动作 |
|---|---|
| 有音频轨 | 必须 ASR |
| 有画面文字 | 必须 OCR |
| 疑引流水印 | 必须扫二维码 / 短链 |
| 疑单帧违规 | 必须高熵定位 + 逐帧 |

这些条件转移写在代码里就够了。

真正需要模型判断的只剩一处：攒到的证据够不够定级。

于是形态是一条确定性主干加一个判据节点。主干把证据取回来。判据节点判断证据是否充分。不充分则定向补证，超过上限转人工。每个状态只暴露它该用的工具：模型在 3 个工具里选，和在 20 个里选，错的概率差很远。处理普通投稿的状态不该读账号完整历史（[Ken Priore](https://kenpriore.com/the-power-vs-control-tradeoff-in-workflow-design-now-with-agents/)）。

### 处置动作为什么放在 Agent 外面

删除、封号、限流的执行器必须在 Agent 子流程边界之外。Agent 输出的是「建议定级 + 证据链」，不是处置动作。这把「Agent 会不会误删内容」这类风险从设计上消掉，而不是靠 prompt 约束。Scott Logic 的贷款例子里，批准/拒绝贷款就在 Agent 边界外；审核场景同构。

生产复盘的经验值：多数流程的 p50 应在 5 步以内、p99 在 15 步以内，超过 15 步基本说明分解错了（[respan](https://www.respan.ai/articles/agent-workflow)）。

### 自由探索放在离线沙箱

新风险的第一批样本没有现成的取证清单，只能边查边定。这时让自由 Agent 在隔离环境里跑，把跑通的高频路径固化成状态机代码，再发布到线上主干。用探索生产流程，用流程生产判定。两条线不能混。

## 04 · 四类工具的返回契约

流程的判断力上限等于它能调到的工具的上限。

工具层设计粗糙，状态机编排得再精妙也是垃圾进、垃圾出。

| 工具 | 必须返回 | 严禁的做法 | 失效模式 |
|---|---|---|---|
| 政策检索 | `Policy_Version_ID`、生效时间窗、豁免条件、类型化字段 | 只做向量相似度匹配 | 拿到已废止条款，判得「有依据地错」 |
| 判例库 | 相似案例作参考字段；物料指纹匹配结果 | 直接复用历史结论 | 画面 99% 相同、性质完全不同 |
| 多模态算子 | 原文切片 + 置信度 + 时间戳 | 只返回布尔值；把超时当阴性 | 「没查出来」被读成「没有违规」 |
| 上下文画像 | 特征更新时间戳 + 实时窗口计数 | 只给离线 T+1 画像 | 刚被盗的号仍显示「信用良好」 |

政策检索最容易被做浅。只检条文、不检例外和生效版本，后果不是判错得离谱，是判得「有依据地错」：引用的条文真实存在，只是已经失效。这种错在申诉时最难解释，因为证据链看起来完整。政策知识库必须是结构化对象，豁免条款以强绑定字段挂在主条文下面。这条和 [SSOT]({{ '/governance/11-ssot/' | relative_url }}) 里「源是唯一能改的那一份」是同一个判断。

判例只能参考，不能短路。「像」和「是」的差别正是判定要处理的。只有物料指纹 100% 匹配、且属于已登记白名单时，才允许复用结论。

取证算子不能只返回 `has_bank_card: true`。判据节点要看到「第 31 秒，置信度 0.71，原文如下」，不是一个布尔值。同时必须区分两类空结果：阴性（查了，确实没有）和调用失败（超时、报错）。算子超时返回空值时，状态机打上 `Evidence_Missing` 标记，绝不能让下游把「没查出来」当成「没有违规」。

上下文画像必须带延迟标注。刚发作的被盗号，离线 T+1 画像还显示正常。接口返回时附带特征更新时间戳，和实时滑动窗口计数一起喂给判据节点。

## 05 · 什么时候必须交给人

强行让 Agent 消化所有疑难杂症，只会把「不确定」变成「高置信度的误判」。系统必须硬编码五条强制转人审出口。

| # | 触发条件 | 强制动作 | 工单载荷 |
|---|---|---|---|
| 1 | 补证达上限（首轮 + 回跳 1 次，共 2 轮） | 停止循环，冻结状态 | 已验证证据项、唯一缺失槽位 |
| 2 | 核心取证工具超时或报错 | 严禁默认放行，转异常队列 | 失败算子名、错误码、原始时间戳 |
| 3 | 跨模态证据强冲突 | 拒绝自动定级，转专家队列 | 冲突双方证据明细 |
| 4 | P0/P1 但置信度居中 | 临时熔断分发，高优转人工 | 高危政策条目 ID、切片定位 |
| 5 | 算力或墙钟预算触顶 | 降级为存疑工单 | 触顶维度、半成品证据链 |

工单不能只传结论。

只给一个「机器存疑」标签，审核员得从头看一遍 47 秒视频，Agent 前面花的算力全部打水漂。工单要高亮已提取的时间戳切片和待确认的单一问题，把人审从大海捞针变成按图索骥的填空题。

高争议样本或申诉复核时，第一屏不能展示模型推理链。审核员会锚定，退化成橡皮图章。工作台先盲判、后展开。高价值样本可启用两个异构模型加一位人工的互不可见多数决，模型意见相反时人票决胜。不同底座模型的输出概率不可比，只能计票，不能加权。这套机制在 [EdgeCase Framework]({{ '/edgecase-framework/' | relative_url }}) 里有完整设计。

### 中间那一档：受限分发

在封杀与放行之间，P2/P3 级低危边界内容可以走第三档：不进公域推荐池，仅粉丝可见，绑定强制 TTL。24 小时内自然互动未触发二次告警则自动归档；热度异动立即提权回流人审。

这一档的风险不在判错，在没人回访。「暂缓」会变永久，进了限流没人看，就成了无人清理的死水。必须有到期时间和责任人，到期默认回人审。P0 不用这一档，明确违法的严格过滤（[KuaiMod](https://arxiv.org/abs/2504.14904) 原文边界）。

## 06 · 三类生产故障与防御

判断一套 Agent 审核系统能不能上生产，不看 Demo 集准确率，看它能不能在周度迭代中不翻车、出了错能不能在 5 分钟内定位到具体哪一跳。

每次执行完毕，落库整次执行的追踪日志，锁死 7 个字段：`Trace_ID`、状态转移路径序列、各算子入参/出参摘要与耗时、`Policy_Version_ID`、Prompt 与模型底座版本、证据字段指针、最终定级与降级原因码。

这套字段服务三件事：申诉时重放、改版时回归、出问题定位到某一跳。结论错了，错在政策检索拿到旧版本、转写丢了关键句、还是判据节点判反，修法完全不同。

只看结论的日志里，它们长得一样。

**模型证据幻觉。** 定级理由格式完美、逻辑严密，写着「画面右下角存在微信收款码」，但 OCR 和视觉算子的原始返回里根本没有这一项。模型顺着高频判例自己脑补了证据。防御是引注指针强校验：每条定罪论据必须附带上游工具返回的原始字段 ID（如 `"evidence_ref": "tool_ocr_output.box_3"`），后置校验发现指针为空或不匹配，直接拦截并转人审。

**策略与工具级联漂移。** 语音转写团队升级了 ASR 模型，或政策团队改了豁免规则表述，没通知 Agent 团队，次日某条分支路径误伤翻倍。防御是路径级回归集加影子模式：把历史上判错并修正过的案例按状态机路径归档，任何工具版本升级或 Prompt 改动，除对比准确率外，必须在影子模式下监控状态转移分布偏移率与工具异常率。

**算力雪崩。** 黑产批量发布多语种混排、模糊二维码的「擦边但不完全违规」视频，故意穿透 L1/L2，打满 L3 工具并发配额，超时熔断的工单涌入人审队列，把人审池冲垮。这是容量型攻击，不是准确率问题（[From Shield to Target](https://ar5iv.labs.arxiv.org/html/2606.14517)）。防御是读写分离加动态削峰：Agent 只出建议工单，执行器在进程外由带速率限制的网关统一执行；实时监控 L2→L3 转化率，突升即为攻击信号，自动将该分支降级为临时限流加异步排队。

## 07 · 回到那条视频

三步并行取证，多花六秒和八倍的钱，保住一个优质创作者的合规内容。这笔账算得过来，前提是 95% 的简单内容已经在前两级漏斗被低成本消化，剩下 5% 走了一条步步留痕、随时可熔断的状态机。

还有几件事没解决。P0 类内容漏放后通常没有用户申诉，召回率不能靠申诉池估计，只能靠外部锚点和主动抽样审计，这条度量路径还没跑通。回归集目前只覆盖判错过且已修正的案例，其余路径没有样本。高频确定性判断从 Agent 卸载回规则引擎的动作还没有做成例行机制，而 L1 与 L3 的成本差是一到两个量级，这是最直接的降本手段。

模型会换，工具会升级，政策会改版。能跨版本活下来的资产是这套骨架：哪一步取什么证、证据放在哪个槽位、什么时候必须交给人。

这个系列的入口在[审核链路]({{ '/governance/' | relative_url }})；判定机制见 [EdgeCase Framework]({{ '/edgecase-framework/' | relative_url }})；政策版本与知识系统见 [SSOT 与迭代流程]({{ '/governance/11-ssot/' | relative_url }})；指标口径见[误伤、漏放与申诉]({{ '/governance/12-appeal/' | relative_url }})。

## 口径与边界

1. **数字性质**：47 秒案例、6.4 秒、9 倍成本、5～8 秒、50～100 倍、5% 占比均为量级示意（来自公开部署数字与预算反推），不代表任一平台实测值。成本倍数有两档基线，引用时连基线一起写。
2. **阈值口径**：50 ms、500 ms–1.5 s、5 s–10 s 是 P99 红线；写进 SLA 承诺必须同时声明统计口径与采样窗口。
3. **时限与配额**：回跳 1 次、5 步以内、24 小时 TTL 是常见取值，不是定论；不同风险类目差别很大。
4. **一手材料缺口**：L2 采样质量指标（STEC, WACV 2026 Workshop）、视频级多帧判定单卡耗时（arXiv:2504.14904）、编排按状态转移计价（AWS T&S 参考实现，1000 次转移 $0.025）见参考。35× 吞吐差中图片侧数据为二手。
5. **不主张什么**：本文不主张 Agent 应该接管大部分审核流量，也不主张 ReAct 无用。它只是不该出现在生产主干上。
