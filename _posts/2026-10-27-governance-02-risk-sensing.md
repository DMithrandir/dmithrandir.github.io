## 〇、先纠正一个前提误区

**❌ 误区**：发现问题只是"数据分析的日常"，是解决问题（部署模型、打击内容）之前的一个准备动作。
**实情**：**在生态治理中，发现问题比解决问题更重要，而且两者依赖的能力完全不同。**

| | 解决问题（M2/M3） | 发现问题（M0）+ 定义问题（M1） |
|---|---|---|
| 依赖什么能力 | **技术驱动**（模型、工程、算力） | **经验 + 价值取向驱动**|
| 产出是否可量化 | **最容易量化**——打击掉一部分内容，立刻能拿到处置量级与低质 VV 变化 | **往往是抽象的**，难以直接量化 |
| 组织内的处境 | 汇报好看、容易获得资源 | 容易被当成"数据分析的日常"，价值被低估 |
| 出错的表现 | 效果不好，指标可见 | **问题本身没被发现**，指标上什么也看不到 |

### 0.1 一个值得写进文档的结构性观察

> **翻看市场上 90% 的生态治理招聘需求，风险感知是一个相对较大的缺口。**即便是面向全链路治理的策略产品岗，JD 里也会突出强调要求"问题嗅觉敏锐度、能通过数据定量定量地挖掘平台风险问题"。
> —— 工作笔记【07】

**这个缺口的成因很清楚，也解释了为什么它值得单独成篇**：

```
可量化的产出 → 容易获得资源与晋升 → 组织里涌现"解决问题"的专家
不可量化的产出 → 难以证明价值 → "发现问题"的能力长期缺位
                              ↓
                    治理体系出现结构性偏科：
              打击能力强（模型越做越好），但总是慢半拍
```

**这构成了一个自我强化的偏差**：组织奖励可量化的事，于是所有人都去优化"已知问题"的打击效率，而**"未知问题"的发现能力持续欠投资**。等到问题以监管通报、舆情事件的形式爆发时，才发现前端根本没有感知能力。

### 0.2 本篇的核心命题

> **风险感知的关键词是「异常」。有异常就会有痛点，有痛点就会有治理需求。**
> 所以风险感知的全部技术含量，在于回答一个问题：**这个异常，是真问题还是噪声？**

这一点与 M1 §四的迭代触发器、M4 §6.3 的归因框架是同一条逻辑——**先判断"是不是问题"，再谈"怎么解决"**。而 M0 的位置决定了它是**唯一在问题形成规模之前就能介入的环节**。

## 一、风险感知在链路中的位置

之前几篇的链路是从 M1 开始的。补上 M0 之后，完整链路是：

```
M0 Risk Sensing（风险感知）
   │  从异常中发现候选问题
   ↓
M1 Policy（规则定义）
   │  判断算不算问题、定严重程度、定处置态度
   ↓
M2 Strategy ──→ M3 Execution ──→ 判罚处置
   ↑                                    │
   └──── M5 Feedback ←── 申诉与质检 ─────┘
              （M4 Metrics 的先行指标）
```

**M0 的三个接口**：

| 方向 | 接口 | 内容 |
|---|---|---|
| **流出**| M0 → M1 | **候选问题清单**（含异常信号 + 初步归因 + 影响面估计） |
| **流入**| M4 → M0 | 指标异常（先行指标与滞后指标的异动） |
| **流入**| M5 → M0 | 用户反馈与外部反馈（被动发现的信号源） |

⚠️ **一个必须建立的判断**：**M0 的产出是"候选问题"，不是"结论"**。
M0 说"这里有个异常"，M1 才说"这算不算问题"。**把 M0 的输出直接当成治理需求，是治理体系最常见的越权**——因为"异常"可能是正常的季节性波动、可能是业务主动调整造成的、也可能只是口径变化（M4 §2）。

## 二、定量分析：发现"是什么"

> **定义**（工作笔记）：基于可量化的数据指标进行分析解读，通过分析异常数据指标，理解线上存在的风险问题，**核心在于发现低质问题"是什么"**。

### 2.1 六大指标渠道与二级指标

> ⚠️ 以下结构完全来自工作笔记的"发现异常指标"图谱，本篇在其上补充**各类信号的性质**与**使用要点**。

| 一级渠道 | 二级指标举例 | 信号性质 | 使用要点 |
|---|---|---|---|
| **C 端消费指标**| 留存、时长、VV | 滞后（结果） | 反映影响面，但**改动后很久才动**，不适合做早期预警 |
| **B 端供给指标**| 内容供给量、品类消费规模 | 滞后 + 结构性 | **供给量下降往往是"误伤"的第一信号**（创作者用脚投票） |
| **推荐后验指标**| 完播率、互动率 | **先行**| 内容质量变化的**最快信号**；且能定位到具体内容/品类 |
| **机审指标**| 命中量、打击率 | 过程 | 反映**已知问题**的打击情况，**对未知问题无感知**|
| **人审指标**| 送审量、处置率 | 过程 + **样本**| 人审是全链路唯一能提供"真值"的地方（M3 §〇），其指标既是产能也是**信号源**|
| **用户体验指标**| 举报率、满意度 | **先行**（举报率抗博弈） | 最直接的"用户认为是问题"的表达；**相对指标天然抗博弈**（M4 §3.1） |

### 2.2 三处需要补充的关键判断

**① 六大渠道有"感知半径"的差异——这是定量的根本局限**

| 渠道 | 能感知什么 | 感知不到什么 |
|---|---|---|
| 机审指标 | **已知问题**的打击效率 | **未知问题**（没规则就没命中量） |
| 人审指标 | 送进来的内容 | **没被送进来的内容**（召回盲区之外） |
| 用户体验指标（举报率） | 用户**愿意并能够表达**的问题 | 用户说不清/懒得举报/不敢举报的问题 |

⚠️ **这是全篇最重要的一个判断**：
> **定量指标的异常，本质上是"已知问题的量变"，而不是"未知问题的出现"。**
> 真正的未知风险，往往在**所有既有指标上都表现为正常**——因为它还没被任何指标捕捉到。

**证据**：快手安全团队明确指出底线风险**仅占千分之几流量**，且对抗变异强（谐音、形近字、AIGC 低成本样本）。而各平台的举报率、机审命中量这类指标，捕捉的正是那"千分之几"——**剩下的长尾与新型变异，是指标体系的盲区**。

**② 举报率是定量的天花板，也是最可靠的地板**

- 作为**天花板**：TikTok 2026Q1 下架 1.84 亿条内容，其中 96.7% 由自动化检出——**自动化是把举报信号放大后的产物**，原始用户举报量远小于此
- 作为**地板**：KuaiMod 的四个取样队列直接把用户反馈翻译成数据源，这是**唯一能自动、持续、规模化获取"用户认为是问题"的机制**

**KuaiMod 的四个队列（可直接借鉴的取样设计）**【论文 arXiv:2504.14904】：

| 队列 | 取样条件 | 反映什么 |
|---|---|---|
| **High Quality Videos**| 人工日审高质量队列、无举报、dislike 率 **<0.1%**| 正例基准（"用户认可的优质") |
| **High Report Videos**| 每日 top-n，单视频举报 **>30 次**| 强烈的显式负反馈 |
| **High Dislike Videos**| top-n，dislike 率 **>50%**| 弱表达但高比例的负反馈 |
| **Negative Comment Videos**| 播放 **>2000**且负面评论占比 **>80%**| **评论区的定性信号被量化**|
| **High-Engagement Videos**（在线精修阶段新增） | 当日最热视频 | **高热内容的风险杠杆最高**（M3 §1.2） |

⚠️ **这套设计的精髓在于"多信号交叉"**：举报、dislike、负面评论是三种不同强度的用户表达，**同时异常才能确认是真问题**。单看举报量会漏掉"用户懒得举报但普遍反感的"内容。

**③ 机审指标是最容易被误用的渠道**

机审**命中量**与**打击率**只反映已知规则的执行情况。**用机审指标找新问题，等于用答案找问题**——没有规则的地方，机审指标永远正常。

**正确用法**：机审指标用于**监控执行质量**（M3 §六），而不是用于**发现新问题**。发现新问题必须靠：
- 用户体验指标（举报、dislike、评论）
- 推荐后验指标（完播、互动异动）
- **定性分析**（下一节）
- 无监督方法（聚类、表征、异常检测）——**这是当前最缺的能力**

## 三、定性分析：解释"为什么"

> **定义**（工作笔记）：对于内容本质的探究和理解，侧重于使用非量化手段来考察对象本身是否具备一定的特质，往往采用**访谈、调研**等方式，**核心在于理解低质问题"为什么"**。

### 3.1 为什么定性分析"应用较少"却不可替代

**应用较少的原因**（工作笔记）：单纯的定性分析具备**抽象性**，不结合定量分析难以量化成风险规模，同时**很难评估治理价值与收益**。

**不可替代的原因**（工作笔记的核心洞察）：

> **生态治理在某种程度上其实是一件"价值驱动"的事情**，首先应该有一个宏观的价值导向在上层做自上而下的牵引。从事内容生态治理的同学，**核心竞争力之一就是应该具备良好的"内容价值取向判断"**。

**技术侧的一手印证**：快手安全大模型的标签生产是**双向**的——
- 自下而上：大模型把内容描述聚合成同类型内容 → 归纳风险元素 → 生成结构化标签树
- 自上而下：**审核规范/平台价值取向决定标签树的层级与粒度**，再人工辅助校验标签与规则条款的映射

**换句话说：标签树的结构不是从数据里"长"出来的，是被价值取向"牵引"出来的。**这就是定性分析在做的事。

### 3.2 推荐的应用方式：定性作为定量的辅助

> **工作笔记的建议**：把定性分析作为**定量分析的辅助手段**——当通过异常数据指标下钻低质问题后，配合调研、反馈等方式进行**佐证**，可以更合理、更低成本地解释问题，帮助后续 policy 定性与应用策略落地环节顺利推进。

**展开成一条可执行的流程**：

```
定量：发现异常        →  "举报率在 X 品类上升 30%"
定性：解释异常        →  "访谈 + 评论分析：用户反感的是'伪科普'话术"（找到了真问题）
                      →  或"调研发现是新品类冷启期的正常波动"（排除了伪问题）
再定量：量化规模      →  "该类话术的 VV 占比 2.3%，影响面确认"
再定性：判断态度      →  "平台认为这属于低质，不属于违规"（M1 的问题定义）
```

**这个流程的本质是「假设 → 检验」循环**：
- **定量发现异常**= 提出假设
- **定性解释异常**= 检验假设（是不是真问题）
- **再定量量化规模**= 确定这个假设值不值得投入

⚠️ **跳过"定性检验"这一步的代价**：会把大量伪问题推进治理链路，占用 M1 的规则产能与 M2 的算力。**M0 的误报成本最终由 M1/M2 承担。**

### 3.3 定性方法的具体形式（补充）

| 方法 | 输入 | 产出 | 成本 |
|---|---|---|---|
| **用户访谈**| 招募典型用户 | 问题感知与用词（**用户怎么描述这个乱象**——这是标签命名的输入） | 高 |
| **评论区/弹幕内容分析**| 内容 + 互动文本 | 用户真实反应（KuaiMod 的 Negative Comment 队列就是它的量化版） | 中 |
| **创作者反馈**| 申诉、工单、社群 | **误伤信号**（B 端供给指标异动的解释） | 中 |
| **专家评审 / 内容价值判断**| 抽样内容 | 价值取向的显性化（M1 标签体系的输入） | 中 |
| **竞品与行业对标**| 同行治理动作 | 我方是否存在同类问题的判断 | 低 |
| **AIGC/对抗样本人工体验**| 新型内容 | 变异形态的早期识别 | 中 |

**"用户怎么描述这个乱象"这一点常被忽略但极有价值**：用户用的词、举的例、说的痛点，**直接就是标签命名的素材**——而标签描述质量在大模型时代是技术资产（M2 §3.3 语义热插拔）。

## 四、主动与被动：两条发现路径

> **前提判断**（工作笔记）：**在风险感知环节，发现越及时，介入越前置，风险越可控。**

### 4.1 主动发现

> **手段**（工作笔记）：各种渠道**巡检、监控报警、竞品调研**等。
> **核心判断**：在工具能力建设上**业内各家基本大差不差**，但是否能够有效利用，就是**另一个能力阶层**的问题。

**这是本篇最实用的一条判断**——因为工具是买得到的，能力买不到。

**一个例子**：
> 当利用监控报警工具发现**一例播放异常飙升**的 case，是否能够考虑到——除分析流量渠道外，还可以同时下钻**增量时间节点、消费用户画像**等维度。

**展开成"多维下钻"检查清单**（一例异常飙升至少问 6 个问题）：

| 维度 | 要问的问题 | 能区分什么 |
|---|---|---|
| **流量渠道**| 流量从哪来？推荐/搜索/关注/站外？ | 是平台推的还是自然发酵 |
| **时间节点**| 增量从几点开始？是否与热点/事件/规则上线同刻？ | **是内容问题还是外部事件驱动**|
| **消费用户画像**| 是新用户还是老用户？是特定人群还是全量？ | 是泛化问题还是**特定人群的敏感**（M1 §1.4） |
| **内容特征**| 该内容与同类内容有何差异？ | 是内容本身还是算法放大 |
| **作者/账号**| 新号还是老号？是否团伙、是否历史违规？ | 是孤立事件还是**黑灰产协同**（M6） |
| **同期对照**| 同类内容是否同向变化？ | 排除大盘波动（M4 §6.1 的 DID 思想） |

⚠️ **最后一条最关键**：不做同期对照，几乎所有"异常"都可能是大盘趋势的一部分。**"异常"的定义天然依赖于参照系。**

### 4.2 被动发现

> **现实判断**（工作笔记）：理想状态下能够通过各种工具能力覆盖线上未知问题当然是最好的，但实际操作中，**低质问题的变异速度与对抗韧度都相当高**，总会有漏网之鱼暴露在各个角落——或是被甲方反馈，或是被老板反馈。
> **核心能力**：**应急处置能力**是最关键的——快速定位问题、准确评估风险水位，**在兼顾用户体验的同时，避免风险持续外溢**。

**注意这句里的两个约束是相互冲突的**：
- **快速处置**（避免风险外溢）→ 倾向于"先下架再说"
- **兼顾用户体验**（避免误伤）→ 倾向于"查清楚再动"

**这就是应急场景下"先审后发 vs 先发召回"的翻版**（M3 §1.1）——同样由误判代价的不对称决定。

**应急处置的三个必备能力**：

| 能力 | 内容 | 常见缺失 |
|---|---|---|
| **快速定位**| 从现象到根因的路径（是内容问题？规则缺失？模型失效？黑产协同？） | 只会"下架"，不会定位 |
| **风险水位评估**| 影响面多大？（VV、人数、是否涉底线、是否外溢到站外） | 用"处置量"代替"水位" |
| **止损与回溯**| 临时手段（硬拦/白名单）+ 事后补规则 | 只有临时手段，没有补规则 |

⚠️ **一个最容易犯的错误**：应急处置之后**不补规则**。事件过去了、指标恢复了，但**规则的缺口还在**——下次同样的问题还会以另一个变体出现。**应急处置的正确收尾动作是开一张 M1 的规则迭代单。**

## 四之二、业界案例：风险感知的四种路径实证

> 本节补充四个可查证的业界案例。**它们的共同价值在于：都证明了"最有效的信号不是内容语义，而是行为与上下文"**——这与 §2.2 的"感知半径"、§三 的"定性分析"是同一结论的不同侧面。

### 4b.1 案例一：抖音 AI 反网暴 Agent ——从"被动等举报"到"主动找风险"

**来源**：央广网 2026-06-12（[中新网转载](http://www.chinanews.com.cn/gn/2026/06-12/10639130.shtml)｜[搜狐](https://www.sohu.com/a/1035700187_362042)）【官方】

**问题背景（原文）**：网暴早已不是直白的辱骂，更多是**表情包阴阳怪气、谐音梗攻击、断章取义带节奏**——这些隐蔽恶意很难被传统审核识别。而传统"人工审核 + 举报处置"有两个结构性缺陷：

1. **依赖用户举报**，等处理时伤害已经造成，**难以提前预警保护**
2. **常规审核只能筛查数天内的内容**，容易遗漏**持续时间长、跨热点周期**的攻击；也无法兼顾未成年人、老年人等不同群体的心理承受能力

⚠️ **第二点值得单列**：它指出了一个普遍存在的**窗口期盲区**——审核的默认时间窗（几天）**短于风险的累积周期**（长期零散骚扰）。M4 §2 讲口径的"时间窗"要素时，这里是它在风险感知侧的对应问题。

**做法：识别模型 + 研判模型双轨，与人工协同**

| 模型 | 职责 | 关键设计 |
|---|---|---|
| **网暴识别模型**| 发现早期信号 | **不再只盯单条评论的关键词**，而关注**用户的整体互动情况**——评论区突然涌入大量负面言论、有人频繁访问某主页、@某账号的异常信息增多 → 计算「**网暴风险得分**」 |
| **网暴研判模型**| 事件级全局分析 | 整合用户**近 30 天**的文字、图片、视频、音频，**还原完整事件脉络**，区分正常观点讨论与恶意攻击；**针对未成年人、老年人设置梯度化识别标准**；输出含**事件经过、风险来源、关键证据**的结论供人工外呼 |

**效果数字（原文）**：

| 指标 | 变化 |
|---|---|
| 日均识别出的**潜在被网暴风险人群**| **+91.5%**|
| 每天主动开启防网暴功能的用户 | **数千名**|
| 因高风险被**人工外呼援助**的受害者数量 | **+147%**|

**保护机制是分层的**（低风险 → App 内提醒 + 一键防护；高风险/特殊群体 → 智能外呼 + 专人一对一）；**处置也是梯度的**（下架内容 → 限制互动 → 永久封禁 → 涉违法犯罪配合公安）。

**⚠️ 一个极重要的机制：全天候复盘误判案例**

> **AI 会全天候复盘误判案例，自主学习新的网暴手段，哪怕是刚流行起来的新梗攻击，也能快速识别。**

这正是 M5 §2.7 的"判例沉淀"与 §四 的"对抗样本库"在**风险感知环节**的实现——**它把"误判"也变成了感知能力的输入**。

**对本篇框架的印证**：

- **从"内容语义"转向"行为模式"**→ 对应 §2.2 的感知半径：关键词只能覆盖已知变体，**行为异常才能覆盖未知变体**
- **从"单条"转向"事件级（30 天上下文）"**→ 对应 §三 的定性分析：单条判不了，要还原脉络
- **梯度化识别标准（未成年人 / 老年人）**→ 对应 M1 §1.4：**同一内容对不同人群的风险不同**，所以是**分层判定**而非统一阈值

### 4b.2 案例二：闲鱼暗语治理 ——"已知拦截"追不上"未知变异"

**来源**：羊城晚报（[新浪转载](https://www.sina.cn/news/detail/5346303754110434.html)）【媒体】

**这是本系列最能说明"定量指标的感知半径"的真实案例。**

**治理投入（原文数字）**：2026 年 1 月至今，累计**冻结涉色情引流账号 98,358 个**，配合警方打掉 **15 个**犯罪团伙。

**但问题没能解决，原因写得很清楚**：

| 环节 | 现实 |
|---|---|
| **黑产手法**| 用「**二手空调**」「**捷安特**」「**苹果卡针**」这类**日常词汇充当暗语**|
| **机审看到什么**| **正常商品名**——系统不认为有问题 |
| **人审为什么也漏**| 人工巡检"**很难第一时间识别出隐藏含义**" |
| **迭代速度差**| **暗语更新堪比"日抛"**，封禁一个，黑产几分钟换一套新话术；而**平台关键词库迭代可能需要数周甚至数月**|

**原文给出的结论（可直接引用）**：

> **审核逻辑始终是"已知拦截"，而黑产的暗语是"未知变异"。**
> 治理关键不在于封了多少号，而在于**能否从"匹配已知暗语"升级为"识别异常行为模式"**。

**它给出的行为信号示例**：

> 一个正常卖自行车的用户，**不会高频发送站外链接、不会批量上架相似商品、不会在深夜集中回复陌生账号**。
> 如果风控模型从"**这个词是否违规**"转向"**这个账号的行为是否符合正常交易特征**"，**暗语的迭代速度就不再是决定性因素**。

⚠️ **这个案例的三重价值**：

1. **它验证了"感知半径"是真实约束**：关键词库 = 机审指标，**只能感知已知问题**（§2.2）；封号数 = 滞后指标，**治理动作密集但水位不降**（§六 的"发现时延"问题）
2. **它验证了行为信号优于内容信号**：暗语会变，**但黑产的变现行为链不变**（导流、批量、深夜集中回复）
3. **它给出了"迭代速度差"这个可量化的诊断**：**Δ = 关键词库迭代周期 − 黑产变体迭代周期**。Δ > 0 时，纯语义匹配必然失效

**平台已经开始的动作**：闲鱼已开始用 **AI 语义识别拦截二维码、短链接等载体**，但**落地效果仍需时间检验**（原文）——这个"仍待检验"的措辞比"已解决"更诚实。

### 4b.3 案例三：快手直播的"举报质量 + 用户情绪"双信号

**来源**：快手微信公众号 2025-11-27【官方】

**原文**："借助深度学习技术，通过**大模型、图计算**等能力强化有害内容和恶意用户的主动识别，结合**举报质量、用户情绪**等维度综合评估判定，同时提升**反哺优化识别模型**的训练效果。"

**三个可提炼的要点**：

| 要点 | 含义 |
|---|---|
| **举报质量**| 不是用举报**数量**，而是评估举报的**质量**——与 M9 §2.2 的"用户身份权重 + 举报信息质量"是同一思路 |
| **用户情绪**| 把**情绪维度**作为独立信号，而非只看行为频次 |
| **图计算**| 用于**恶意用户**识别——这是"从内容转向主体"的技术路径（对应案例二的结论） |

**配套效果数字**：低俗直播举报率同比 **−55%**；部分低俗违规内容**识别时效从分钟级降至秒级**。

### 4b.4 案例四：多信号交叉 ——抖音"AI 求真"的谣言库

**来源**：科技日报（[原文](https://www.stdaily.com/web/gdxw/2026-05/25/content_522153.html)）【官方】

**做法**：机器判定与人工判定的结果**共同入库形成"谣言库"并自动复用**，实现"**人找谣言 → 模型主动出击**"的转变。判断准确率 **95%**，被处置谣言平均浏览量 **−62%**。

**可提炼的机制**：**把"已确认的判定"沉淀为可检索的资产**——与 M0 §2.2 的 KuaiMod 判例库、M9 §3 的举报异常池是同一种思路：**结论复用让感知能力随治理量增长，而不是随治理量消耗**。

### 4b.5 四个案例的横向对照

| 案例 | 感知信号 | 覆盖的问题类型 | 可复用的机制 |
|---|---|---|---|
| **抖音反网暴**| **行为序列 + 事件级上下文（30 天）**| 隐蔽恶意、跨周期骚扰 | **识别模型 + 研判模型双轨**；梯度化识别标准；**误判复盘自主迭代**|
| **闲鱼暗语**| 语义（失效）→ **行为**| 未知变异（日抛暗语） | **从"词是否违规"转向"行为是否异常"**；迭代速度差 Δ 的诊断 |
| **快手直播**| **举报质量 + 用户情绪 + 图计算**| 低俗、恶意用户 | 质量而非数量；情绪维度；主体图分析 |
| **抖音 AI 求真**| 机器判定 + 人工判定共同入库 | 谣言 | **判定结果自动复用**，形成主动出击能力 |

**四案例的共同结论（本篇可用的最强论据）**：

> **有效的风险感知信号，普遍不是"内容里说了什么"，而是"谁、在什么时候、以什么方式、和谁一起做的"。**
> 因为**内容可以伪装，行为与关系难以伪装。**

### 4b.6 一个可以直接用的新概念：语义对抗的「速度差」

从闲鱼案例可以抽象出一个**可量化、可诊断**的指标：

```
Δ（迭代速度差） = 平台的规则/词库迭代周期 − 对抗方的变体迭代周期
```

| Δ 的取值 | 含义 | 应采取的路径 |
|---|---|---|
| **Δ >> 0**（平台慢得多） | 纯语义匹配**必然失效**| 转向**行为模式 + 关系图谱**；语义只用于已知问题 |
| **Δ ≈ 0**| 语义匹配勉强可用 | 语义 + 行为并行 |
| **Δ < 0**（平台更快） | 语义匹配有效 | 可优先投入词库与规则（成本更低） |

**闲鱼的现状**：词库迭代**数周~数月**vs 暗语迭代**几分钟**→ **Δ 极大**，所以原文说"治理关键不在于封了多少号"。

**这个概念的通用价值**：它把"该用行为识别还是语义识别"从**技术偏好问题**变成了**可测量的问题**——先量 Δ，再选路径。

## 五、定量与定性的关系（本篇的核心判断）

工作笔记给出了"定性作为定量的辅助"这一实际操作建议。在本系列的框架下，还可以再往前推一步：

> **定量与定性的分工不是"主辅"，而是"发现"与"确认"——它们构成一个「异常检测 → 假设检验」的闭环。**

```
        定量：发现异常（是什么）              定性：解释异常（为什么）
        ───────────────────────              ───────────────────────
    优势：可规模化、可持续、能自动告警         优势：能识别"没被指标捕捉的问题"
   ❌ 盲区：只能感知已知问题的量变              ❌ 盲区：无法量化规模，难以评估收益
                    │                                     │
                    └──────────► 交叉验证 ◄───────────────┘
                                    │
                        两者都指向同一结论 → 真问题（进 M1）
                        只有一方支持      → 继续观察 / 补数据
```

**为什么必须双向**：
- **只有定量**→ 系统性错过所有新型风险（因为新风险在所有既有指标上都正常）
- **只有定性**→ 无法判断值不值得治理（工作笔记已指出：抽象、难量化规模、难评估收益）

**一个重要的推论**：
> **当定量与定性结论冲突时，应该优先相信定性，然后用定量去找"为什么指标没反映出来"**——因为指标没反映出来本身就是一个需要解释的现象（通常是**口径问题**或**指标盲区**）。

## 六、风险感知体系的校验三维度（与前几篇平行）

| 维度 | 核心指标 | 过程指标 | 说明 |
|---|---|---|---|
| **发现能力**| **新型风险的发现时延**（首次出现 → 被感知） | 巡检/报警的触发量、下钻维度覆盖率 | 决定"是否慢半拍" |
| **判断准确**| **候选问题的成案率**（进入 M1 后被确认为真问题的比例） | 伪问题回流数、重复提出的问题数 | 决定 M1 的产能是否被浪费 |
| **前置程度**| **发现时点 vs 规模化时点**（越早越好） | 首次发现时的 VV 占比、是否早于外溢 | 决定"介入是否前置" |

### 6.1 为什么"发现时延"是最关键也最难测的指标

**难点**：分子（首次出现时间）**不可知**——你不知道问题第一次出现是什么时候，只能知道"我什么时候发现的"。

**工程解法**（建议）：
- 用**回溯法**：问题确认后，回溯指标历史，找出"最早出现可检测信号的时点" → 该时点与发现时点之差就是发现时延
- 用**外部锚点**：监管通报、媒体报道、竞品治理动作的时间点，作为"外部已发现"的基准线
- 用**黑产视角**：对抗样本库中出现新变体的时间 vs 我方感知时间（M6）

⚠️ **"候选问题成案率"是最容易被忽略的指标**：如果 M0 提出的候选问题里只有 10% 被 M1 确认为真问题，那 M1 有 90% 的产能在处理噪声。**M0 的误报是有成本的，只是成本记在 M1 账上。**

## 七、常见反模式（自查表）

| 反模式 | 表现 | 根因 | 修法 |
|---|---|---|---|
| **用机审指标找新问题**| 机审指标平稳就认为没新问题 | 机审只能反映已知规则 | 用体验指标 + 定性 + 无监督方法 |
| **只做定量不做定性**| 新型风险总是慢半拍 | 缺价值驱动与假设检验 | 定期调研，建立"定性确认"环节 |
| **只做定性不做定量**| 结论抽象，拿不到资源 | 无法量化规模与收益 | 定性后必须补量化 |
| **发现异常即当问题**| 伪问题占用规则产能 | 跳过检验 | 多维下钻 + 同期对照 |
| **不做同期对照**| 把大盘趋势当异常 | 缺参照系 | DID 思想（M4 §6.1） |
| **异常不归因到渠道**| 不知道是内容问题还是算法放大 | 下钻维度不足 | 六维下钻清单（§4.1） |
| **应急处置后不补规则**| 同类问题换个变体再来 | 缺收尾动作 | 应急结束必须开 M1 规则迭代单 |
| **只盯头部/热点**| 长尾风险长期积累 | 资源集中在高热 | High-Engagement 队列之外保留长尾抽样 |
| **以处置量代替风险水位**| 汇报"处置了 X 万条" | 未评估影响面 | 报 VV 占比与外溢情况 |
| **感知结果直接当治理需求**| 跳过 M1 定义直接上策略 | M0 越权 | M0 只出候选，M1 定性质 |
